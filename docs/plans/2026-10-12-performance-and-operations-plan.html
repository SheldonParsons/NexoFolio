01持久化任务队列 P0后端 · 合同 · 任务入口 · 基础步骤+ 500–800生产新增行 · 估算⌄

为什么做

现在开始整理就直接启动工作。资源不足或启动响应丢失时，缺少一个持久、可查询的排队身份；下班关闭页面以后也必须能追踪同一任务。

做到什么效果

合法请求先落库再返回接受；资源不足时排队。同项目、同范围的重复提交复用任务，不同范围串行；不同项目公平轮换。

具体实施

  1. 在 knowledge 模块增加任务元数据、幂等请求身份、租约及执行代次；runtime 统一领取和恢复任务。
  2. 排队只保存身份和范围，实际运行时才读取最新资料并冻结输入。任务落库失败时明确显示“尚未提交”。
  3. 新增按任务 ID 查询和停止的接口；保留原开始、续跑及候选应用入口。
  4. 发起者身份用于后续权限核验，不保存登录密码或临时令牌；关浏览器和会话到期不取消已接受任务。

为什么需要这些代码

代码分布在合同、队列规则、PostgreSQL 持久化、领取/恢复与 HTTP 适配五处。可靠排队需要原子领取和旧执行者隔离，不能只加一个内存数组。

是否合理

合理。复用现有 PostgreSQL 与恢复机制，不建设通用任务平台；若突破上界，先检查是否存在两套重复恢复逻辑。

重复点击只得到同一未完成任务；资源不足仍接受合法任务；重启后队列和已保存批次仍在。

02持续重试、续跑与停止 P0后端 · 模型调用 · 进度 · 依赖 01+ 200–340生产新增行 · 估算⌄

为什么做

实测连续模型 503 约 60 秒后整理失败；上游恢复后继续观察 22 秒，未自动续跑，手动同候选续跑成功。这是任务生命周期问题，单独调大超时解决不了。

做到什么效果

临时故障持续退避重试，已保存结果不重做。明确的配置、资料冲突或反复无效输出进入“需要处理”，而不是把普通故障当整轮终点。

具体实施

  1. 统一临时错误与待处理问题的分类；保留单次请求超时，取消临时故障的整轮累计重试上限。
  2. 持久化下一次重试时间，随机错峰并遵循 Retry-After；等待时释放运行位置和模型许可。
  3. 排队、等待和执行分别计时。模型合理表达未知是有效候选，不无限追求无法验证的答案。
  4. 主动停止不自动重启；应用部分成果时原子停止剩余任务。上游调用期间不持有数据库事务锁。

为什么需要这些代码

主要改写现有三个阶段的错误收尾和重复重试分支，增加一套共享规则及持久化等待状态。模型适配器已有并发退让，应继续复用。

合理，且是本轮最有实测依据的改动。删除重复循环应抵消一部分新增量；不重写整个 LLM 客户端。

04冻结输入分块与准备阶段内存 P1后端 · 新快照格式 · 双读兼容 · 依赖 01–03+ 450–750生产新增行 · 估算⌄

为什么做

501 接口、25,010 条人工字段说明的压力输入，准备后统计 29,010 个字段；首个模型请求前就观察到约 1.26 GiB 内存。整份 PreparedProject 和序列化对象反复复制是重点。

做到什么效果

完整资料按接口和文档分块保存、共享不可变索引，执行时按批读取。降低驻留内存，保持全局分析范围和证据完整。

具体实施

  1. 增加版本化清单、内容哈希与按接口分块输入；原始文档、字段输入和关系索引通过引用复用。
  2. 按接口读取样本并生成输入，完成后释放临时对象；减少整份项目对象 clone 和完整 JSON 中间对象。
  3. 执行器只装载当前批次所需输入；缓存必须有容量上限，不能把分块读又变成无界全量缓存。
  4. 新任务写新格式；旧任务保留兼容读取和续跑路径，不强制改写正在运行的旧快照。

05候选结果增量投影 条件实施后端 · 候选保存 · 事务 · 依赖 04 与保存基准；先判定再实施+ 600–1,000生产新增行 · 估算⌄

为什么做

当前每批有读取、复制并写回整份候选视图的路径。项目变大后，小改动可能带来大的写入放大，但应先测它在优化后的实际占比。

做到什么效果

基线保持不可变，批次仅追加变更并更新对应投影，避免每个小批次重写整份项目文档。

具体实施

  1. 先执行保存专项基准，确认全量候选复制/写回仍是主要成本。
  2. 仅当它导致内存目标未达成，或保存 P95 超过 500 ms 等明确瓶颈时启动本步骤；500 ms 是验收判据，不是运行限流。
  3. 按字段/接口保存变更和投影，保留同一事务内的状态、执行者、版本与名称校验。
  4. 候选浏览和应用按范围读取；保留旧候选兼容，不能为减少 JSON 而跳过基线与废弃状态校验。

06MCP 数据库检索与归档按需读取 P1后端 · 查询端口 · MCP · 依赖 04 的分块读取；与 05 的条件判断解耦+ 220–380生产新增行 · 估算⌄

为什么做

做到什么效果

数据库先筛选、计数和分页，只返回当页所需字段。精确字段及观测值读取只装载相关内容。

具体实施

  3. 分页保留来源版本校验与 next.arguments，实时调用计数变化不造成无意义重读。
  4. 复用 04 的分块/归档格式；这里只计读取与分页代码，不重复计迁移代码。11 个工具及完整语义入口保持。
