# 两层目录整理与稳定身份

2026-10-07。已实施，真实项目按钮验收待前端完成后统一进行。

## 输入与产出

输入是完整接口清单（方法、路径、中文名、用途及有界详细说明），现有目录 ID/父级/介绍，以及接口当前归属和人工标记。目录阶段不读取原始样本，不自行重复生成字段说明。

模型返回第一层业务模块、第二层功能分组，各分组用本次接口编号明确列出成员。未能分类的接口必须明确列出原因。路径作为理解资料，不再作为 `contains` 匹配路由；同一路径的不同方法也能分别分组。

产出仍是正常 knowledge Command：目录新增/更新、接口归属变动。公共 Catalogue 保持扁平数组加 parent 引用，前端无需更换读取协议。Folder 新增可缺省 author；目录和接口的 UUID 路由保持原义。

## 职责

| 位置 | 职责 |
|---|---|
| interpretation/directory_prompt | 准备完整语义清单、旧身份和人工保护提示 |
| interpretation/organize | 调用模型并解码严格的两层 JSON，不决定 SQL 或更新规则 |
| planning/catalogue/identity | 明确旧 ID、同名、完全相同成员的身份复用；拒绝人工/未知来源元数据覆盖 |
| planning/catalogue/validate | 唯一接口归属、层级、父级、同层名称、最终顶层上限、新目录有效成员及共享身份保护 |
| planning/catalogue/reconcile | 生成最小差异及合法写入顺序；不删除共享目录 ID |
| runtime/curation/directories | 读取现有知识和归属、执行模型步骤，通过正常轮次一次提交命令 |
| knowledge | 目录作者、层级约束、事务、历史与回滚；提交时再次检查人工保护 |

## 身份和更新规则

- MAX_DEPTH 从 3 调整为 2；新生成结构的业务模块下有功能分组，接口归入第二层。人工归属仍优先，既有人工直接放在一级目录的接口不强制搬走。
- 优先复用模型明确引用的旧 ID。没提供 ID 时，同父级同名优先；唯一且完全相同成员的已知生成目录可以支持改名；不再挑第一个旧目录随意改名。新增接口时允许合理扩充已有同名目录。
- 旧的有成员目录不能被复用为完全不同且有成员的另一组接口，防止同一分享链接静默换成别的业务内容。目录分拆、移动或有共同成员的调整可以进行；此规则不代表已自动验证业务分类质量。
- 缺少新介绍时保留旧介绍。相同目录属性和归属不写命令，不新增无效变更历史；目录阶段目前仍会调用模型，没有实现持久的目录输入哈希/模型调用跳过。
- 未出现在建议中的旧目录保留，可为空，以保留已有链接。不创建新的空目录；旧空目录自动合并/别名退休不在本次范围。
- 所有接口必须恰好出现一次，既不能遗漏，也不能先匹配先占用。未知编号、未知/重复旧 ID、第三层、重复归属、同层重名及超限最终树均拒绝整份建议，原目录不被部分覆盖。
- 先给变动的旧目录使用唯一临时名称并将其根化，再写最终父子结构，避免同名子目录移动、改名交换和旧三层迁移造成 SQL 冲突。全过程同一事务，临时状态不对读者可见；历史记录可逆。

## 人工与旧数据

Folder.author 与实际写入轮次一起保存，历史 Before 与恢复同样保存作者。新增迁移 `202610070003_folder_author.sql`，不改旧迁移。旧数据只有全部未回滚历史均为自动整理时，才标识为生成内容；有人工历史或无历史的记录保持未知并保护，不用轮次开始时间冒充实际最后写入顺序。

模型读取之后可能有人编辑。knowledge 在项目事务中再次检查当前目录/归属作者，拒绝自动覆盖人工及未知目录、移动/取消人工归属；相同归属是 no-op，保留人工作者。受保护冲突使该批目录变更整体回滚，已完成的其他整理阶段保留。

已知生成的旧三层目录可以在保留全部 ID 的前提下调整成两层，旧历史仍能恢复原状态。未知/人工三层数据不会被凭空认作可自动改写。

## 验收边界

固定模型测试校验完整清单、语义编号、结构与更新处理；真实隔离 PostgreSQL 验证一层→两层、重复零写入、改名、同名移动、回滚、旧三层兼容、作者迁移及并发人工保护。真实模型业务分组质量和真实项目页面必须在最终按钮验收中另行检查。
