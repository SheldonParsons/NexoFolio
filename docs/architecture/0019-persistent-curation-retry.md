# 持续重试、续跑与停止（性能计划第 02 步）

2026-10-12。承接 [持久任务队列](0018-persistent-curation-queue.md)，仅改变任务恢复与必要进度合同；不新增全局运行面板、通用任务系统或生产调参入口。

## 错误与执行边界

- `CompletionError` 保留网络、单次超时、HTTP 状态、共享冷却、请求配置和无效回复类别；runtime 不再根据中文或 HTTP 文案猜测类型。
- 网络、超时、408、429、5xx 交给同一持久队列持续恢复，无整轮累计重试期限。HTTP 其余拒绝、请求构造错误、权限或冻结资料/基线冲突、反复无效输出进入 `needs_attention`。
- 请求仍保留 10 秒连接、150 秒总请求超时；运行监督、租约和字段批次的有界无效回复修复仍在。移除阶段外重复的字段收尾补跑，不叠加无限循环。
- Describe/Fields/Organize 的无效回复修复次数按接口、字段或阶段保存在候选进度中；重启和临时故障不会把已记录的次数清零。模型明确解释证据不足属于有效的未知候选，保持原有 candidate 确认语义。
- 上游错误正文、提示词、令牌和密钥不进入任务原因或审计。配置修复后使用原“续跑本轮”；无法安全复用冻结输入时，停止旧任务并从原入口开始新一轮。没有候选的待处理提交可由有权用户重新提交同范围恢复。

## 持久状态与调度

`queued → running → waiting → running`；明确问题进入 `needs_attention`；完成、主动停止或关闭候选进入终态。

- 新迁移追加 `next_retry_at`、原因代码、重试计数和状态计时。`waiting/needs_attention` 属于未完成范围，参与幂等和活动列表；等待不占全局运行槽或模型许可。
- 等待及待处理任务保留项目内位置，后续同项目任务继续排队；其他项目可领取。继续时复用同一任务、候选、冻结输入和已确认保存的批次，领取增加 generation/run_id，旧 owner 仍被拒写。
- 普通临时故障退避基准为 10、20、40、80、160、300 秒，附加 0–20% 基准随机错峰；合法 Retry-After 秒数或 HTTP 日期取不早于服务要求的时间。它们是可复跑的初始策略，不是生产容量调优结论。
- 共享 429/503 冷却沿用适配器；遇到冷却时返回给持久队列，不把执行器留在内存休眠。仅因共享冷却延期不再追加指数等待，避免健康项目持续排在故障项目后面。
- 同一短项目事务保存候选检查点及任务等待/待处理状态，随后退出执行器。没有跨模型调用的数据库事务。若数据库不可用导致保存未确认，不伪造成功状态；原持久身份保留，数据库恢复后由既有过期租约领取恢复。
- `TaskTiming` 累计排队、执行、等待三种持久状态的时间；查询和前端只延续当前状态的计时。执行时间包含模型许可排队及 IO，不等同模型实际推理时间或 CPU 使用量；无法确认存储状态时不宣称已进入持久等待。

## 停止与候选决策

- 用户停止等待、排队、运行或待处理任务后，清除重试时间；上游恢复和进程重启均不会自动重新领取。
- 已冻结的等待候选保持 `partial` 可审阅、可应用；应用部分成果在原事务内同时停止剩余任务。准备期间尚无完整冻结输入的候选保持原恢复语义。
- 父候选 apply/discard/cancel 同事务关闭关联的等待/待处理任务及运行子候选。保留部分成果、冻结资料和历史；清空的活动任务检查包含新增状态。
- 第一阶段的同范围幂等、不同范围串行、项目公平领取、发起者授权、审计身份、提交/观察独立和 task_id 晚到响应隔离保持不变。

## 进度与诊断

现有进度面板显示排队、执行、等待恢复、需要处理，展示原因、下次尝试和分别计时；等待不展示运行心跳或运行动画。活动任务选择器包含新增状态；待处理任务可停止，已保存成果仍可查看。

`curation.suspended`、`curation.resumed/RETRY_DUE` 复用原有有界、尽力写入的审计 sink，携带既有 task/run/generation 和发起者身份。没有新增 outbox 或恰好一次投递保证。外部模型调用也不保证恰好一次计费；已确认保存成果与执行权按原事务栅栏保护。
