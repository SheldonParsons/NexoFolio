# 独立业务项目与受限清空

2026-10-10。业务项目可在 NexoFolio 独立创建，绑定一个或多个已同步的真实禅道项目作为操作权限来源。一个禅道项目可以对应多个独立业务项目；不修改禅道，不复制成员关系，不迁移已有资料。

## 权限与发现

创建、编辑、权限来源查询、清空预览和清空接口仅接受已登录、启用、数据库保存的账号为 A80646 的用户，大小写不敏感。其他身份，包括匿名、普通项目成员、过期凭证和 MCP 凭证，统一返回 404；在验证身份后才解析业务参数。

普通登录与 `/v1/auth/me` 为该账号返回 `capabilities.manage_projects=true`。前端同时检查可信能力与当前账号；其余账号不渲染创建按钮、管理菜单或弹窗。编辑入口仅显示在本地独立项目上，真实禅道项目仍由禅道同步维护。资料更新仅在同一身份下保留已验证能力，收到管理接口 404 时移除管理入口。

`access.projects` 区分 `zentao` 和 `local`：本地项目没有外部项目 ID，必须绑定同实例、已同步的禅道项目。创建接口拒绝本地项目作为权限来源，避免链式继承。同步仍只更新真实禅道项目。

`effective_project_access` 统一派生权限：普通用户只要拥有任意一个绑定项目的同步授权，即可操作本地项目，A80646 沿用全项目访问。网页操作、环境管理、MCP 发现、逐次读取准入和可访问项目计数共用这个规则。权限变更沿用普通登录同步时机。

MCP 保持 11 个只读工具。现有凭证可发现新业务项目，所有资料按新项目自己的 ID 读取；权限继承不会合并父项目的环境、接口或知识。网页公开只读策略保持原规则。

## 管理接口

- `GET /v1/project-management/permission-sources?page=1&limit=50`
- `POST /v1/project-management/projects`：`name`、`permission_source_project_ids` 数组（1–100 个不同的真实禅道项目）。仍兼容单来源旧参数 `permission_source_project_id`，两个参数不能同时提供。
- `GET /v1/project-management/projects/{project_id}`：读取可编辑的本地项目名称、全部权限来源及 `revision`；同步项目返回 404。
- `PATCH /v1/project-management/projects/{project_id}`：提交 `name`、`permission_source_project_ids`、读取时的 `revision`。版本冲突或重名返回 409，不能覆盖另一个窗口的修改。
- `GET /v1/project-management/projects/{project_id}/content`：接口、采集结构、目录、整理结果和运行中整理的数量。
- `POST /v1/project-management/projects/{project_id}/clear`：`confirmation` 必须与当前项目名称完全一致。

`project_permission_sources` 保存多对多绑定，外键同时限制实例和项目来源，禁止绑定本地项目形成继承链。新增迁移将旧单来源绑定原样转入此表；项目 ID、数据及配置不变。删除绑定不会复制或删除成员授权，MCP 原有凭证在下一次调用使用更新后的规则。禅道自身授权的刷新仍依赖既有普通登录同步时机。

创建和编辑共用表单，通过项目名称多选，至少保留一个绑定。编辑只更新 access 模块内的名称、版本与绑定，不修改任何接口、整理结果或环境配置；共享活动屏障让编辑与清空互斥，允许整理同时继续。版本检查在行锁内执行。

管理响应禁止缓存。清空前有运行中的整理或项目写入时返回 409；应先停止整理和暂停 Fetcher，再重试。前端不自动重试创建或清空，提交期间禁止关闭弹窗。

## 数据边界与事务

删除选中项目全部环境的接口、别名、指纹及原始样本、声明、变化事件、目录、归属、接口说明、字段说明、关联、整理候选、冻结输入、字段值归档、轮次与修改历史。

保留项目身份、名称、状态、权限绑定、环境及别名、站点绑定、服务地址判断、基础路径配置、用户、凭证和独立的后台操作记录。服务地址调用统计归零。其他项目（包括共用权限来源的项目）不清空。

access 提供持有项目互斥屏障的调用方事务；应用层只编排。knowledge、observe 的适配器使用同一连接，执行各自 schema 内的 SQL，复用各自写锁，不跨模块操作表。任一步失败整个事务回滚；跨项目的异常级联引用拒绝清空。端点别名一次删除，避免临时恢复别名时触发身份唯一性冲突。

普通项目写入和 intake 提交持有共享活动屏障，清空持有独占屏障。屏障使用独立的有界连接池，避免占满业务查询池；请求结束或取消时自动释放。路径参数通过路由器解码，编码后的 UUID 同样受保护。

运行中的候选不允许清空；已停止或结束的候选删除后，旧执行者的落库和自动恢复找不到候选，不能恢复内容。提交后只移除匹配旧执行 ID 的本地进度缓存，避免取消清空后刚启动的新轮次。

保留 intake 回执和 observe 去重标记（不含请求响应正文）。observe 持久化清空时间，在写锁内忽略 `observed_at` 不晚于清空时间的旧观测，防止历史缓冲和重试回灌。时间来自采集记录，因此重新采集要求客户端时钟正确；清空不是永久禁用项目，之后的新采集仍正常入库。

## 发布与验证

切换到新版 API 前执行对应的 `nexofolio-admin migrate`，随后启动新版后端并更新前端。access 的 `202610100003_multiple_permission_sources.sql` 将单来源列迁移为绑定表；管理接口必须与新版后端一起切换。原有迁移文件保持不变。

验证使用独立 `nexofolio_access_test_*` 数据库、模拟用户与采集资料，不执行真实项目清空或真实模型调用。覆盖管理接口隐藏、权限继承与撤销、MCP 原凭证发现、跨项目隔离、清空范围、别名、并发屏障、旧观测、自动恢复拒绝及注入失败后的完整回滚。浏览器测试拦截所有 API，覆盖入口隐藏、创建、确认、忙碌、失败重试、权限失效和移动端。

本功能及账号策略不加入公开更新日志。
