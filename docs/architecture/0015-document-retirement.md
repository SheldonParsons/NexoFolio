# 目录、接口、字段的废弃与撤销

2026-10-11。本功能属于项目共享文档的生命周期，覆盖全部环境；不改变证据的 candidate / observed / confirmed 状态，不删除原始样本。

## 状态与边界

- knowledge 保存 `document_lifecycle` 当前状态和 `document_lifecycle_history` 版本历史。事务沿用项目写锁，状态、操作人、原因、时间、版本一同提交。
- 接口决定覆盖附属字段。目录决定冻结当时的目录子树，覆盖结构和介绍，不废弃其中仍有效的接口。字段目标包含接口、位置和路径段，包含子字段，避免用字符串前缀误判相邻名称。
- observe 继续拥有采集事实与别名。新增只读 identity 投影只取规范 ID 和别名，不为生命周期读取加载样本。采集、别名合并和旧候选应用不能撤销决定。
- `version` 每次废弃/撤销递增；`reconciled_version` 仅在同版本的全项目完整候选成功应用时推进。单接口或部分结果应用不能宣称全项目核对完成。
- 同级名称唯一性只作用于有效目录，由 knowledge core 在已有项目写锁内统一校验；直接写入、候选应用、回滚和撤销废弃共用此规则。历史目录保留原名，不占用新目录的名称。撤销若与当前有效目录同名，整次操作不保存，提示先废弃或调整同名目录，之后仍可撤销。
- 旧目录、说明、字段和关联行保留以支持原链接与证据读取。有效视图和候选投影按生命周期排除废弃对象。全项目应用在同一事务中解除废弃接口/目录的旧归属，保留修订记录；失败会整体回滚。撤销后保留原资料，下一轮重新分类与核对。

## HTTP 与权限

`GET /v1/projects/{project}/document-lifecycle` 读取项目状态；`POST` 提交：

```json
{"target":{"kind":"field","endpoint":"UUID","location":{"in":"request_body"},"path":[{"key":"data"}]},"retired":true,"reason":"旧参数已被替代","expected_version":3}
```

目录目标为 `{"kind":"folder","id":"UUID"}`，接口目标为 `{"kind":"endpoint","id":"UUID"}`。撤销使用同一直接目标及 `retired:false`。后端验证登录、现有共享项目权限、对象所属项目、字段精确存在和版本。409 表示版本变化，重新读取后再决定；不自动重试写入。只有直接决定可以撤销，继承状态应管理其来源。

公开文档响应携带状态和来源废弃提示，仍采用原公开资料白名单。公开读者不能调用管理接口。新增操作不引入角色或账号专属限制。

## 候选、冻结输入与恢复

`KnowledgeSnapshot.lifecycle` 保存候选开始时的持久版本及决定，参与基线哈希。工作投影还记录读时解析的别名。创建候选时排除废弃目录、接口、字段、关系和旧归属；待核对版本清除自动说明和字段的复用哈希，保留未废弃人工内容。目录按原全项目流程重新分析，不增加整理模式或按钮。

冻结输入显式保存 `lifecycle_version`。整理前仅在内存投影中排除废弃字段及取值，包含容器内的旧子字段；原始采集报文和历史归档不写回、不修改。整理值归档根据有效投影重新提取，废弃字段不再建立新索引；裁剪后的父对象值标为部分资料，不冒充完整原始报文。

继承、手动续跑、服务重启恢复、应用均检查基线/生命周期版本。运行中变更不会删除候选或主动停止 worker；读取进度时标示 `lifecycle_stale`。停止与新一轮仍沿用原有单任务限制。旧候选可以审阅，不能沿用旧冻结资料续跑或应用；服务重启后的过期任务保留为中断状态，不无限重试。

候选列表、默认入口及手动选中的历史入口统一在读取时比较冻结基线和当前项目生命周期版本，返回 `progress.lifecycle_stale`，并关闭过期轮次的续跑入口。冻结版本来自 `base.lifecycle.version`，不信任旧进度中的同名值；初始未检查点及旧格式按冻结基线的默认版本处理。摘要不读取原始样本、不修改保存的进度；界面自己的废弃/撤销操作复用现有整理读事件使浮窗立即刷新，不新增轮询。

应用先锁项目并核对版本，再验证候选归属和关联、执行旧归属清理及生成批次，最后验证有效投影并原子提交。LLM 调用不持有该事务。全部接口废弃时可生成没有有效接口、字段和关联的结果，不调用模型；未选中废弃的目录内容保持其独立状态，不隐式覆盖人工介绍。

## MCP

保持 11 个只读工具。项目/环境发现及内容返回提供生命周期提示；名称入口保持渐进式披露。搜索、目录浏览和接口读取增加可选 `include_retired`；返回历史展开动作，精确 ID/字段读取继续返回已存在对象。分页/分块修订绑定生命周期版本，变更后要求重新开始该次读取。

默认目录视图把“仍有效接口指向废弃目录”的归属视为待分类，目录计数也使用同一有效范围；不改写历史归属。精确目录读取及历史读取仍可沿原归属查看。`include_retired=true` 随目录、接口、字段和关联的可执行入口继续传递，仅保留目标工具接受的参数。

有效内容优先；关联到废弃来源的有效对象保持自身状态，另给来源提示。有效依赖遍历排除已明确失效的端点/字段关系，历史关系仍可展开。证据确认不自动改变；自由文本的所有语义依赖不承诺找全。原始请求/响应值不因生命周期提示被篡改。

## 迁移与验证

迁移：`modules/knowledge/adapter/migrations/202610110001_document_lifecycle.sql` 和 `202610110002_active_folder_names.sql`。后者解除覆盖历史行的旧名称唯一索引，统一使用项目事务内的有效目录名称校验；不删除或更名历史资料。需随后端二进制一起更新；现有项目默认版本 0。项目受控清空沿用原有事务，包含这两张新表。
