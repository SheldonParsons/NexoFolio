# 现行统一重构

本文描述收敛后的工作区代码。旧目录生成服务、模型适配器、CLI生成命令和可写任务端口已退出生产代码。只保留已有历史资料的读取与激活，不再提供第二套生成机制。

## 唯一新生成流程

`POST /v1/projects/{project_id}/maintenance-runs`（请求仅含`request_id`）→权限校验与固定知识快照→`maintenance_runs`持久任务→worker的`MaintenanceEngine`→统一候选→用户另行发布。

没有新旧生成器选择，没有按数量阈值自动创建任务，没有MCP重构工具；触发器目前只保留意图接口。CLI保留历史只读catalog-show，不再有catalog-create、catalog-run、catalog-preview。查询任务、打开页面不会创建任务。

## 输入

- 项目所有已建档且有环境当前修订的接口：ID、方法、路径、各环境ID/名称、当前修订和观测定义。
- 字段完整索引：请求参数/头/body、响应头/body、层级/数组结构、原定义指针、完整性及不足说明。
- 项目路径识别策略给出的模板提示。
- 当前正式目录、接口归属、展示合并组；尚无归属的新接口补为固定待分类。
- 当前已发布说明、关系、枚举及其定义依据；修订不匹配的资料标为待复核。
- 项目已经形成的证据事实：观察值、标签/字典映射、参数关系/反例、页面、交互、元素和图片引用。结构取当前修订；facts查询并未只筛选当前修订，因此历史事实通过字段引用和版本区别处理。
- 项目目录/知识版本、generation、目录指标、上一轮已发布维护结果，以及尚未完成证据处理数量。以前模型结论不是新的独立证据。

整个项目及所有环境固定为本轮快照，调用方不能指定只看某环境/目录/接口。新录制数据留到以后；未完成处理的数据只计数，不伪称已被审阅。原始请求/响应、页面材料及图片通过快照引用按需读取，不把全部抓包历史和二进制一次性送给模型。

## 四种策略的实际边界

所有策略都先完整审阅，策略决定的是结果怎么改，不是读取多少。

| 策略 | 允许的目录变化 | 代码拒绝的变化 |
|---|---|---|
| keep | 保持整个catalog（含归属/展示组）不变；仍可维护语义 | 任意目录结果变化 |
| insert | 新增目录、给待分类接口安排归属、新增展示组 | 改动/删除原目录、移动已分类接口、改动/删除原展示组、整树替换 |
| partial | 以现有目录为基准，逐项增改删节点、调整归属或展示组 | replace_catalog整树替换动作；其他引用/覆盖规则同样检查 |
| full | 整体替换目录，或用完整的动作组合整理 | 漏掉快照接口、破坏固定待分类、无依据/越界动作仍拒绝 |

partial/full不按“修改了百分之多少”自动区分：partial是逐项动作，full才有整树替换权限。新增/修改/撤回参数说明、关系、枚举可以与任一种策略组合。接口独立name/title尚未定义，description不是名称字段。

## 模型执行过程

1. 建立完整导航索引，按输入预算切分字段；同一接口放得下时保持一起审阅。
2. 每个字段返回审阅记录，机械核对每个单元恰好覆盖；缺读/未知引用不能继续发布。
3. 汇总全局发现，结合当前目录及证据决定四种策略和具体动作。
4. 修改前核对目标及依据：字段说明读目标字段，关系读两端，目录修改读受影响分支和边界，事实读固定样例原文。
5. 小型原文直接进入下一次规划调用，成功返回后才记完成；大原文分片，图片单独读取。未开启视觉或未成功解读不能记图片已读。
6. 根据动作生成完整候选，校验目录覆盖/保留项、证据、字段修订、枚举类型与范围；不合格会有限反馈修正，仍不合格则incomplete。

目录结构检查仍有最多500个目录节点、候选最多10000个动作的上限。默认快照64MiB，模型上下文配置65536、单次最多240秒、总调用256次、失败有限重试。配置可调整；不是耗时承诺。预算不足或覆盖不完整明确停止，不切换为抽样或旧生成器。worker可恢复同配置下租约过期任务的检查点；没有自动把失败任务重新创建为新快照的逻辑。

## 产出

首先产生待审阅的统一候选，而不是立即变更正式知识：

- `plan`：策略、选择理由、预期收益、具体动作列表。
- `catalog`：应用动作后的完整目录、归属和展示合并组。
- `annotations`：应用动作后的完整语义集合，包括说明、关系、枚举、证据引用、观察/推断/待复核性质、来源任务和定义依据。
- `review/coverage/issues`：结构检查、阅读覆盖、阻止发布的问题。
- 任务快照、审阅和原文读取检查点、模型请求/结果和可选usage，供解释和排错。

目录操作为新建/更新、删除、归属调整、整树替换、增改/撤回展示组；语义操作为增改/撤回注释。说明不改原字段类型；合并组不物理合并接口；少量观察值不能声明完整枚举；仅未再出现不能证明枚举应删。

## 发布的确切动作

用户有当前项目访问权限，并显式提交`request_id`与`expected_generation`。应用层使用人工发布策略；所有版本激活进入同一个事务。

1. 重新鉴权，锁定项目版本行，查询是否已有相同幂等回执；同请求重试原样重放，冲突复用拒绝。
2. 检查当前generation、任务ready、完整覆盖、候选和计划重新物化一致。
3. 检查快照中各接口/环境的当前定义修订是否仍一致，避免发布过期字段知识。
4. 目录有变化时追加catalog_versions及节点/归属；只改语义时复用原目录版本。
5. 目录或语义任一有变化时追加knowledge_releases，保存目录版本与完整语义集合。
6. 同一事务切换当前目录/知识版本指针，generation增加，并保存回执；失败整体回滚。
7. 完全没有变化时不创建新版本、不增加generation，但仍有幂等回执，changed=false。

发布不重新调用LLM，不修改原始请求/响应或观测结构，不做物理接口合并、不处理结构裁决、不删除新进入的接口。快照之后新增接口仍通过固定待分类显示。普通用户不能改名、删除或移动固定待分类。

统一回退恢复目标知识版本对应的目录和语义；目标null回到两层初始状态。历史目录专用激活只切目录并保留当前语义，通过同一事务实现，是历史数据兼容而不是第二条重构路径。迁移202609150006只终止旧pending/running生成任务，保留已有快照、完成候选与发布版本。
