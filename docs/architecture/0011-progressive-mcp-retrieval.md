# Agent 主导的渐进式知识检索

2026-10-09。实现目标：信息可达、默认轻量、范围明确、依据可核对。运行中的服务是否已经加载这些能力，以实际 initialize / tools/list 为准。

## 职责

- Agent 选择检索路线、读取深度、补查与停止时机。
- MCP 只授权、校验参数和投影已有事实/正式知识，不执行 SQL、模型、整理写入或业务 HTTP。
- knowledge core 提供目录与归属的一次读取、正式字段知识批量索引；adapter 在本模块表上实现读取。
- knowledge 的复合读取使用 repeatable-read / read-only 事务。观察事实属于 observe 的独立读取范围，不声称跨模块存在永久全局快照。
- 目录、搜索、接口、资料、来源和覆盖检查分别组织为小模块。保留旧 read_interface 组合读取和旧字段值读取协议。

## 11 个入口

list_projects、list_project_environments、browse_directory、search_interfaces、read_interface、read_request_material、read_response_material、read_field_values、read_source_evidence、trace_dependencies、inspect_knowledge_coverage。

读取可以产生平台审计记录，但不修改知识、候选或业务数据。

每个工具有独立公开参数表，运行时拒绝其他工具的参数和非法枚举。内部请求 DTO 仅用于投影共用的范围与分页信息，不把全部参数暴露给每个工具。

browse_directory 默认只列直接子目录；接口成员需要 section=interfaces，子树需要 recursive=true。未分类和全部接口始终有入口。目录名称、介绍和归属来自正式知识，不现场生成。

search_interfaces 默认查询名称/用途/方法/路径，search_in=fields 查询正式字段名称与说明的索引，返回所属接口和字段引用。通用字面词匹配，不维护业务场景专用同义规则。字段索引不加载原始 HTTP 样本；尚未整理的字段通过 read_interface 的字段事实读取，不能将索引空结果当作字段不存在。

read_interface 的 overview / description / fields / field / relations / samples 区分摘要、完整说明、直接子字段、单字段、关系和样本索引。字段使用带位置的 key；关系可以按字段和方向缩小。字段文字保留原样，结构化证据保留相关接口引用和确认状态。只有文字提及的关联由 Agent 搜索核实，不写回新关联。

## 完整性与续读

摘要均有全文或对象展开入口。新的分页返回 total、has_more、next_offset、revision 和可直接调用的 next。完整资料返回 JSON 文本块，按 next 连续取完后再解析。

分页 revision 约束范围、对象、正式说明和目录上下文；实时调用次数及最近调用时间不冻结，不单独导致重读。原文分块 revision 对完整选中文档计算，保留所有原始业务字段。它不是永久项目版本。范围或数据变化返回 SOURCE_CHANGED_RESTART_READ，必须丢弃该次旧片段重读。样本同时核对 source_record。偏移使用服务返回值，不在客户端猜测 UTF-8 字节或 UTF-16 长度。

请求/响应保留重复 Header、正文状态、原文与根值；页面/操作上下文单独读取。未保留样本、未捕获响应、无上下文、原文截断与完整空值分别表达。读取不新增脱敏或凭证替换策略；历史业务认证仍不能证明当前有效。

## 验证边界

自动回归覆盖结构化关联跳转、文字线索搜索、字段索引不读样本、目录与环境、嵌套字段、长响应重组、来源变化、授权、参数边界和真实 TCP/JSON-RPC。

Codex + GPT-6.1 Sol 的模型工具选择和商用订单管理系统的业务检索由用户实际验证。自动测试不代表这项已经通过。11 个是当前收敛方案，没有声称它在真实模型上一定比 17 个更准确。

覆盖检查只统计保存事实和正式说明中的已知缺口。尚未采集的业务能力及语义正确性不在保证范围；完整工具调用审计仍是独立能力。

## 第二轮：字段语义层与覆盖汇总

保留 11 个方法。字段入口推荐 field_summary：完整语义、状态和少量关联引用，证据、完整关系和原值按下一跳读取；field 的旧完整资料快照保留。说明和未知点不截断，长语义仍可分块。

覆盖检查新调用可显式选择 summary 了解分布，也可用 issues / issue_kind 或单字段范围直接读取相关明细，顺序由 Agent 按任务选择。没有新增参数的旧调用保留原明细分页；使用新筛选参数即选择现代明细。生成完成度复用公共 FieldNote::generation_addressed，与整理规划使用同一纯判定；明确未知也可能已处理，不改变业务确认等级。

source_reads 只从结构化引用构造动作，不预取原文、不猜缺失 ID、不自动跨所选项目/环境。失效引用有样本索引入口，但替代样本不能充当原证据。

错误由只读层统一类型化，旧 error 字符串保留并增加 details。数值越界给范围及建议值；字符串过长给长度约束，不回显或自动改写业务文本。审计仍使用稳定错误码。

## 第三轮：导航投影减重

不新增工具、请求参数或服务端引用缓存。显式 fields 的 key 已表达精确位置与路径，节点省去重复结构化 path；完整结构仍可通过同一 key 的 field_summary / field 取得。仅有可见直接子字段的节点提供 expand，所有节点继续提供可直接执行的完整语义入口。

父键和子节点数量在一次字段列表内预计算，保留原位置、环境可见性及孤立子字段的根级回退行为，避免为每个节点重复遍历全部字段并重建父路径。

字段搜索保留接口身份、方法、路径、名称、用途、目录及字段名称／说明预览；只保留 matched_field.open，不再重复附带接口概览动作和逐环境流量。需要接口上下文时仍可用返回的 endpoint_id 与页面范围读 overview。接口搜索和目录接口卡片保持原返回形态；旧组合读取、完整字段和完整语义层保持原协议。

limit 原先已有 1–50 的 schema 边界，第三轮补充参数说明、发现工具提示与服务指令，建议首次省略分页参数。不将一次 limit=100 的误用认定为 schema 缺失，也不宣称文字提示可以保证模型不再误选。

## 整体使用指引与自主检索

2026-10-10。知识服务的 initialize.instructions 通过编译期 include_str! 装入 `apps/backend/src/mcp/instructions.md`，集中说明理念、资料结构、用途、收益、完整读取和证据边界。未装配导航的基础服务仅说明工具不可用，避免空列表被解释成项目没有资料。

指引解释目录、搜索、字段、关联、原文和覆盖视图分别支持哪些判断；入口、顺序、深度、范围调整和停止时机由 Agent 自主决定。减少无关上下文和重复读取是结构收益，不能因此截掉业务语义或阻止必要的全量读取。覆盖工具描述同样改为介绍可选视图，不要求先 summary 后 issues。

来源、环境、时间、确认状态和缺口是 Agent 可以利用的核对信息，不意味着开放后台工具调用历史查询。检索只读边界、授权、分页范围、同版本续读和旧调用兼容均不改变。

前端的用户说明和动态接入话术共用 mcpPurpose 表达用途与收益，网页及无脚本完整参考使用相同生成函数。整体指引是否被客户端完整交给模型、模型是否利用得当，仍需在实际客户端会话中验证；初始化返回指引不能代替模型使用效果验证。
