# 访问与操作审计

实现于 2026-10-09。用于访问趋势与问题排查，采用有限缓存、尽力写入；它不是保证零丢失的合规账本。

## 查看权限

- 前端 `/settings/audit`，工作空间右上角“审计”入口。
- 仅认证后的账号 `a80646`，账号比较忽略 ASCII 大小写（`A80646` 同样允许）。前端入口、页面和路由共用同一规则。服务端每次调用 `/v1/audit` 都先验证会话，再读取用户档案，校验用户 ID、启用状态、准确账号；不信任前端、自报账号或请求参数。
- 匿名返回 401，其他账号返回 403；审计响应 `Cache-Control: no-store`。无公开管理口、无额外管理员 token。数据库与服务器运维权限仍需由部署环境管理。

## 采集内容

| 类型 | 内容 | 默认保留 |
| --- | --- | --- |
| 页面 | 首页、产品文档及工作空间的首次导航和路径变化；同一小时、路由、用户或 IP、项目合并计数 | 30 天 |
| 接口 | 路由模板、方法、项目、用户或 IP、HTTP 状态、次数、总耗时和最慢耗时，按小时合并 | 30 天 |
| 核心操作 | 整理请求、后台开始和结束、补跑、取消、应用、废弃的操作、结果、请求 ID、候选 ID | 90 天 |
| MCP | 实际 tools/call 的工具名、用户、项目/接口 UUID、结果码、耗时与请求 ID；JSON-RPC 的业务失败不会被 HTTP 200 掩盖 | 90 天 |
| 问题 | HTTP 5xx/408、后台整理未完成或保存失败、浏览器错误类型、网络/超时/非法响应，保留请求 ID 用于关联服务日志 | 30 天 |

已知用户来自服务器验证的 session/MCP principal，记录稳定用户 ID；无法识别则用 IP。无可靠连接地址时记录 unknown，不猜测。登录成功请求也会关联用户。关键整理业务历史原有的事务性记录保持独立，不随审计淘汰。

不存密码、token、Cookie、请求/响应正文、URL 查询参数、用户输入、原始异常 message/stack、模型提示词与返回内容。浏览器问题目前记录类型和页面位置，不上传原始堆栈；具体整理问题可凭候选 ID 读取已有进度/批次详情。普通访问不保存逐请求明细或完整 URL；同一类资源的路径参数归并到路由模板，项目 UUID 单独保留。

页面是客户端报告，不能作为不可伪造的业务操作事实。禁用 JS、拦截上报、静态下载的 `/api.html`、`/mcp.html` 或 Markdown、网络中断不会完整计入页面次数。IP 不是独立访客 ID；共享出口合并、动态 IP 变化均会影响人数解释。小时汇总的日期边界按整小时统计。

## 请求影响与容量

- 请求侧只创建结构化小对象、更新共享身份、`try_send` 到有限队列；不等待审计数据库，不复制请求正文，不为普通 API 额外查身份。
- 独立单连接 PostgreSQL pool、独立 `audit` schema；只锁审计计数行，不锁业务表。
- 普通队列 4096、重要队列 1024；批次最多 256，空闲每 2 秒刷写，积压时连续刷写，关键记录优先且给普通记录预留吞吐。
- 写入有 3 秒总超时、SQL 2 秒和锁 500ms 超时。失败不重试，避免未知提交结果造成重复计数；异常记丢失计数及结构化告警。进程崩溃可能丢失尚未写入的记录。优雅停止尝试在已有停机时限内排空。
- 默认明细最多 100,000 行、小时汇总最多 100,000 行。计数、写入和按最早时间淘汰在同一事务内，多个实例写入也受统一行数上限约束。
- 每分钟按期限清理，每张表每轮最多 5000 行，避免大删除事务。单条明细 JSON 不超过 2 KiB；字段另有限长。队列大小、存活行数和单条大小都有上界。
- 这是记录数上限，不是严格的磁盘字节配额。索引、WAL、死元组、备份另占空间；autovacuum 复用空间但不保证文件立即缩小。界面展示表和索引实际大小与容量淘汰数。部署原有容器日志已轮转为 10 MB × 3，其他运行方式也应设置日志轮转。
- 浏览器最多 60 次上报/分钟，其中错误最多 10 次，最多 4 个在途请求；服务端最多 120 次/IP/分钟、全进程 1200 次/分钟，入口正文最多 2 KiB。丢失数字是当前后端进程队列/存储损失，不包括浏览器拦截和限流；多实例需结合各实例日志。

## 配置与上线

先执行原有显式迁移命令 `nexofolio-admin migrate`，再启动新后端、发布新前端。API 不自动迁移。数据库不可用或迁移未执行时业务保持可用，但审计写入会失败并产生告警。未配置登录能力时不暴露审计查询或前端上报入口。

| 环境变量 | 默认 |
| --- | --- |
| NEXOFOLIO_AUDIT_ENABLED | true |
| NEXOFOLIO_AUDIT_MAX_EVENTS | 100000 |
| NEXOFOLIO_AUDIT_MAX_BUCKETS | 100000 |
| NEXOFOLIO_AUDIT_OPERATION_DAYS | 90 |
| NEXOFOLIO_AUDIT_ERROR_DAYS | 30 |
| NEXOFOLIO_AUDIT_ACCESS_DAYS | 30 |
| NEXOFOLIO_AUDIT_TRUSTED_PROXIES | 空 |

可信代理必须填写实际受控代理的**连接来源 IP**，逗号分隔，不支持通配。默认忽略转发头。只有连接来自可信代理时，才从 X-Forwarded-For 右向左跳过可信代理并取第一个非可信地址；无效链回退连接地址。现有 Nginx 配置会追加来源地址。原生同机后端通常是 `127.0.0.1`；Docker 场景需核实实际桥接网关地址，不能照抄同机值或信任任意私网 IP。

上线前应核对代理 IP，否则访问将被正确但不够精细地归于代理地址。生产部署、生产迁移、重启不包含在本次隔离验收中。

## 查询

`GET /v1/audit` 支持 actor（`user:UUID` / `ip:IP`）、project、kind、route、request_id、since、until。默认最近 7 天；区间最多 366 天，每类返回最新 200 条。访问排行榜是筛选区间内按路由汇总的前 50 个，不受 200 条明细展示上限影响。查询请求 ID 时不展示无法按请求追溯的访问汇总。
