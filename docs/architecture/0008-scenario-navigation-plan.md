# 场景导航优先：接下来的实施步骤

状态：实施方案，2026-10-07；尚未实施。此方案根据用户明确的核心场景调整优先级，取代先完善目录与文字、再接 MCP 的实施先后。完整整理产出流程仍见 [0007](0007-curation-workflow.md)。

第一验收标准：agent 通过 MCP 找到能完成用户目标的接口，追溯认证、输入来源和真正前置条件，形成适用于当前环境、业务端和已有输入的调用路径，并在可控场景中完成目标及核对结果。

## 本轮范围：之前确定的整理优化全部保留

场景导航调整的是优先级。此前的名称、描述、字段、目录和持续成长均为明确交付项，不能只笼统归到“最后完善文档”。关键场景的说明与关系在第 3 步一起产出；其余接口在第 6 步逐批推广。两层目录及对应前端是第 7 步的独立交付，不以第一条场景闭合为实施前提。

| 优化项 | 明确要做的内容 | 所在步骤/状态 |
|---|---|---|
| 证据提取 | 请求/响应位置、父级/兄弟对象、类型和值、页面/顺序、认证载体；先匹配相关记录再限制模型摘要 | 第 3 步 |
| 接口名称 | 必要业务范围、动作和对象；解决同名歧义，保留已有好名称 | 第 3 步关键接口；第 6 步其余接口 |
| 接口描述 | 短用途及主要输入、输出、ID 角色、观测场景、关联和未知事项 | 第 3、6 步 |
| 字段中文名称 | 真实 JSON 键保持原样；中文显示名独立保存，区分直接来源和推测 | 第 2 步合同；第 3、6 步生成 |
| 字段描述 | 基础含义、实体角色、单位、值含义、条件、来源和未知项；修复已核对的错误说明 | 第 3、6 步 |
| 字段及接口线索 | 异名值传递、多字段一致、列表详情、字典/配置和认证；去除通用值噪声，记录条件与可靠程度 | 第 2、3 步；第 4 步通过 MCP 可读 |
| 持续成长 | 首轮就记录来源/版本；新证据影响旧名称、描述、字段和关系；目录根据相关变化更新，未变结果复用，人工修订和历史保留 | 第 2、3 步建立最小机制；第 6 步全项目完善 |
| 两层目录 | 层级生成和校验、旧树差异、稳定归属、后端与前端递归展示、搜索展开祖先 | 第 7 步独立交付，可在前面阶段单独落地 |
| 对象数组展示 | “每个元素(object)”不独占行，元素说明和依据仍可展开 | 已完成，不重复实施 |
| 其他前端查看 | 中文名、分层说明、上下游关系、参数来源、条件和证据可核查 | 第 7 步 |
| 代码结构 | 沿用已经拆分的证据、规则、规划、解释、存储和 transport，保持模块和文件规模检查 | 全过程 |
| 不过度推断 | 有证据才补值含义、单位和前置；未知项保留；没有关系允许空 | 全过程 |

同结构新值的持续保存属于后续采集/观测任务，继续保留为明确后续工作；它不冒充本轮整理已实现的能力。

## 1. 先确定一个端到端验收场景

优先采用现有“保存并提交技术咨询”接口，明确测试目标为“创建并提交一张技术咨询单”。“只保存草稿”是另一种目标，不能替用户默认包含提交动作。

为此场景列出：目标操作、业务端与环境、用户已有信息、可用认证状态、需要准备的参数、各参数可能的来源、已知业务条件、知识缺口及结果核对方式。

最少验证四种情况：

- 未登录且提供所需任务信息：规划认证及必要的取值/检查/提交步骤。
- 已有有效业务登录：复用当前认证状态，不重复安排登录。
- 用户已提供有效项目/商品 ID：按需要核对或补充其他信息，不为取得已知 ID 重复查询。
- 缺少输入或缺少可靠资料：区分应询问用户的内容和应补充的知识，不用历史样本中的 ID、token 或未知类型值冒充本次输入。

**产出：** 一个明确场景、可验证的输入条件、路径期待和缺口清单。最终以实际目标完成和结果核对验收，文档齐全不单独代表闭环完成。

## 2. 定义可用于导航的关系，而不只是附加说明

每条关系至少记录：源接口/字段、目标接口/字段、方向、作用、适用环境/业务场景、触发条件、原始证据、确认程度和版本。

区分以下含义：

| 关系 | agent 如何使用 |
|---|---|
| 认证使用/认证依赖 | 当前业务请求怎样携带凭证、何时需要取得有效凭证；使用观测与强制要求分开 |
| 参数取得 | 某个响应可提供目标缺少的输入；同时检查来源接口自身需要哪些输入 |
| 条件前置 | 某种状态或操作下才需要的步骤，例如有明确依据的验证码或业务条件 |
| 业务前置要求 | 有声明、明确业务确认或验证支持的强制步骤 |
| 推荐预检 | 已观察到或有依据建议执行的检查，未证明强制时明确标注 |
| 字典/配置及实体参考 | 帮助理解或选择值、核对实体；不默认加入每条调用链 |

观测到 A 在 B 之前发生，不足以把 A 标成所有 B 的强制前置。同值关系也不足以证明 A 能帮助当前用户取得未知值。

认证记录提供认证方式、载体和凭证引用，不把历史密码或 token 作为任务输入。MCP 访问 NexoFolio 的权限与目标业务系统的登录状态分别处理。

**产出：** 可持久化、可追溯的关系和字段知识合同，支持来源、条件和状态。仍由 knowledge 保存和记录历史，避免另外建立一份脱节的场景数据。

## 3. 优先提取能支持路径的证据与关系

先处理与验收场景及已验证关系相关的资料：

- 认证载体、凭证字段及来源关系；凭证值仅用于受控比对，知识结果保留方式和脱敏引用。
- 目标请求的参数角色、业务对象、实际类型，以及来源 API 的输入/输出。
- 异名参数对应、同条对象的多个字段一致、列表/详情、选项/请求等关系。
- 同一操作的页面、顺序、环境和业务端；这些是观测依据，不自动代表权限或硬依赖。
- 字典/配置的 value/name、条件要求及消费字段的适用关系。

规则匹配与给模型的摘要分别控制范围，先找相关记录再截取模型输入，避免再次遗漏数组第 20 项。

模型负责表达含义和摘要，规则负责可核查匹配；模型建议的关系要带证据或保留候选身份。当前接口名称与基本说明可用于最初检索，对关键歧义优先补充操作、范围、主要输入和输出，不等待所有字段文字优化完成。

这一阶段同时更新关键接口的名称、用途与详细描述，生成字段中文名及分层说明，并纠正已核对的错误。单位、中文配置和 value/name 配对是存在时使用的来源，基本解释仍使用英文名与真实上下文。不把资料生成和依赖知识拆成两套保存结果。

首轮至少覆盖已核对的咨询子单号、响应码、报价编码、缩写展开、参数 ID 角色等错例；合理的旧名称和说明保留。对未变化内容建立复用判断，对新证据导致的更新记录理由。

**产出：** 优先场景的有依据关系、接口名称与说明、字段中文名及描述、可用输入说明和待补材料清单。关系不是一个手写死的固定调用序列。

### 本次补核对出的两个关键边界

- 项目详情返回的 `data.id` 与创建请求 `opptyProjectId` 相同，同页面 seq 5 → 10；但查询请求本身的 `id` 就等于该项目 ID。它可以核对或补充已知项目的信息，不能在用户只有项目名称时直接提供未知项目 ID。当前这份返回也没有找到对应创建 `opptyId` 的值。
- 创建请求含 `Authorization: Bearer ...`，但其凭证不匹配已保存的两次管理端登录响应。不能把已有验证码/登录样本直接拼成已验证的供销云创建完整链。需补证据确认适用的登录方式和凭证来源，或在已有当前有效认证的验收条件下复用认证。

补材料针对真实缺口，可采用定向场景采样、有效接口声明或明确业务确认，不扩大成无边界的采集平台重写。

## 4. 提前接通最小 MCP 导航能力

当前 MCP 为基础骨架，没有注册知识工具。首轮至少提供三类能力：

1. 找目标：按用户目标、操作、环境和业务范围检索接口，并区分创建、提交、处理任务等动作。
2. 读目标：读取接口真实输入输出、认证信息、字段知识、依据、条件和未知项。
3. 沿关系查上游：定位参数来源和前置条件；来源接口也可继续追溯，返回缺口、候选和后续读取入口。

场景追溯以当前用户已有输入和认证状态为条件，跳过已经满足的依赖。区分值发现接口与需要同一已知值的详情接口；遇到循环、没有来源或不确定强制性时，明确返回原因。

查询从已保存知识读取；MCP 不在每次查询时调用模型生成新解释。图的读取和检查限制展开规模，agent 可以继续逐步读取，避免一次塞进全项目所有字段。

**产出：** agent 可使用的检索、读取、依赖追溯能力和带条件/缺口的路径资料。首轮不用建设大而全的 agent 执行平台；实际业务调用由受控测试中的 agent 工具完成。

## 5. 用真实 agent 把场景闭合

通过 MCP 找目标、读取资料、反向追溯并准备输入，然后在可控测试环境验证调用及结果。

验收关注：

- 目标选择正确，用户的创建目标与保存/提交动作一致。
- 使用正确业务端和环境；认证及必需输入准备完整，参数按来源映射。
- 已有输入和有效认证被复用，不加入菜单、表格配置等无关页面请求。
- 条件步骤有条件，推荐检查和已确认前置不混淆。
- 不套错枚举，不用历史样本值冒充当前任务值。
- 同值但不能提供缺失输入的关系不会导致无限回溯。
- 对业务返回和实际创建结果进行核对；HTTP 200 不单独代表创建成功。结果未确定时先核实，避免盲目重复提交。
- 缺口有定位依据，补齐后重新验证，而不是宣称路径已经完整。

再选择任务处理或非标配置作为第二场景，验证这些机制能复用，而不是只为创建咨询写一条特例链。

**产出：** 真实 agent 的场景验收记录及修正后的知识。第一条闭环完成后再推广到其他场景。

## 6. 将关系、文字与持续更新统一起来

有新的参数来源、认证关系、字典映射、条件或验证结果时，更新受影响的关系、字段解释、接口说明和可用场景资料。没有相关变化的知识复用，人工修正和历史保留。

中文名、描述和线索来自同一份带来源的知识，不分别维护一套生成结果。可以保存已观测的流程片段；当前任务的执行路径要结合用户状态和输入生成，不能把一个历史流程当成所有任务的唯一顺序。

相同结构的新值持续保存仍属于采集/观测的后续能力；本轮在已有证据范围内更新，并针对闭环必需的缺口补材料。

将首轮机制逐批应用到其余接口，检查接口名称与描述、字段中文名、说明、线索和来源的完整性。全项目完善不代表所有字段都必须生成确定答案；未知业务含义继续保留。目录根据接口业务内容或归属规则的相关变化计算更新，单纯调用数量增长不要求重新生成所有文案。

**产出：** 全项目逐批完善的名称、描述、字段及关系知识，明确的新旧差异、复用与更新记录。已验证场景能获得新版本而不是永久固定。

## 7. 完善两层目录和前端查看方式

继续完成此前确定的两层目录、字段中文名与描述优化。目录按真实业务模块与功能分组，支持人和 agent 缩小检索范围。

前端重点展示：本接口需要准备什么、参数从哪里来、有哪些上游与下游、关系依据是什么、哪些条件和内容还未知。原始字段名、中文名和详细解释共用相同知识。

**产出：** 两层目录和便于核查的文档界面。目录和文字改进服务场景导航，不阻塞第一条 MCP 闭环。

## 代码职责

| 位置 | 负责什么 |
|---|---|
| curate/evidence | 提取原始值、类型、同条记录、场景和非敏感认证方式等证据 |
| curate/rules | 独立的认证、参数取得、条件及实体对应规则；带来源和确认状态 |
| curate/planning | 更新影响判断；对给定目标、已有输入和认证状态进行纯依赖追溯及缺口判断 |
| curate/interpretation | 将有依据的知识表达成中文名称和说明，保持候选身份 |
| knowledge | 保存和查询关系与来源、版本、修改历史，不直接执行业务接口 |
| MCP transport | 权限、参数与输出；通过公开端口读取知识和调用纯追溯逻辑 |
| runtime | 整理任务的读取、并发、进度和写入，不决定业务依赖 |

新增关系类型按独立规则和脱敏回归样本加入。继续遵守模块依赖、schema 所有权、统一事务、文件职责和规模检查。
