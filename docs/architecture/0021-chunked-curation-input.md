# 0021 — 分块冻结输入与按需执行

状态：2026-10-13 本地实施；迁移和验收仅使用隔离数据库。范围为性能计划第四步。

## 数据所有权与格式

knowledge 继续拥有候选、冻结资料、事务、项目隔离和租约校验。runtime 组织读取与执行；curate 保留纯资料分析和模型解释规则。

新增 `knowledge.frozen_input_chunks`，按项目、候选、准备尝试 UUID、SHA-256 定位不可变文本块。使用 UTF-8 JSON 文本保留任意精度数字；字节数和 SHA-256 在读取时核验。复合外键将块绑定到同项目候选，项目内容清空沿候选级联删除，不能跨项目级联。

候选 `execution_input.version=3` 保存清单与恢复元数据。清单内部版本为 1；内容包括接口索引、字段块键、文档引用与全局关系引用。`manifest_hash` 覆盖整个 v3 头部（排除哈希自身），因此有序接口范围、生命周期版本、基线批次与引用身份一起受校验保护。

旧版 v2 保存记录保持原样，从原 JSON 读取。没有重新采集或重新生成来代替旧格式续跑。旧值归档继续走旧读取路径；新格式按接口组合字段索引和原始文档，沿用相同观测值 API。

## 准备过程

1. 从候选基线取得生命周期、接口范围与已继承批次。
2. 逐接口读取完整样本，生成事实、认证线索、观测值索引和文档；及时写块并释放正文临时对象。
3. 内存保留全部 SampleField 信号及接口身份摘要，构建一次 ProjectEvidence 索引。全局导航和模板规则的参数明确为完整接口摘要与完整信号；规则没有删减。
4. 逐接口读回自己的冻结资料，利用同一全局索引生成字段输入。保留既有值代表选择、未知状态、字段哈希和证据规则。
5. 字段块沿用现有 `FIELD_BATCH_LIMIT=12` 划分；单个字段的资料不截短。原始文档只保存一次，字段和观测值通过引用关联。
6. knowledge 在候选所属项目事务中核对当前 owner、任务 generation/租约、完整清单、每块内容哈希、观测值所属接口及文档指针，最后才发布清单。

分块写入不是可执行标记。发布前断电只留下未发布块；原任务恢复时建立新的准备尝试，不能把旧尝试的半份输入拼进新清单。已发布后禁止继续追加冻结块或替换清单。

准备分析运行在一个阻塞计算任务中，项目索引通过只读借用共享。该任务通过已有知识端口读写，没有另建调度器；停止后迟到写入仍受现有 owner 和租约校验拒绝。

## 执行与恢复

新格式启动和进程重启后，都从数据库逐块核验完整资料，再进入任何模型调用。缺块、哈希不符、清单/范围/项目/候选/尝试身份不匹配进入已有冲突与待处理路径，不能回退到实时数据。

说明阶段待处理队列只保存接口身份与之前的说明；装载活动接口时才形成完整模型输入。字段阶段先逐接口计算原有批次边界，队列保存字段键；工作者只读取命中当前批次的字段块，其他正文随作用域释放。一个物理字段块可能包含相邻字段，解码后只保留本批字段。

没有进程级正文缓存：容量为零，无需要标定的缓存初值。正在工作的接口或字段块仍受原执行并发上限约束。不能把本机测试的并发或内存值当作生产容量参数。

v2 的兼容读取仍需解析历史整体输入，不承诺旧格式也获得与新任务相同的内存降幅。解析时避免先复制整份 JSON 值。新任务和新保存均使用 v3。

原候选基线、view 和 batches 的投影方式保留。每批保存和人工应用的版本/废弃校验、父子关闭、已保存批次恢复规则继续由原 knowledge 事务处理。应用 v3 候选前额外核对冻结资料完整性；损坏资料不能被应用。

第三步运行状态继续使用原有六字段小检查点，观察接口不读取分块正文。没有增加管理功能或改变 MCP 的 11 个只读方法。

## 迁移与边界

部署支持 v3 的 API 前需要新增迁移 `202610130003_frozen_input_chunks.sql`。迁移只增加复合唯一约束和分块表，不回写既有快照、值归档、批次或运行中的旧任务。用户数据库本轮未迁移。

旧二进制不能执行新格式任务；回退时必须保留支持 v3 的读取能力和数据，不能删表或把 v3 任务标成已完成。长期回收未发布块和已结束任务资料仍属于后续清理步骤，本步没有引入定时清理。

本轮有一项测试基础设施修正：内存知识存储原本声明不支持并发事务，新的计算任务暴露了其全状态覆盖竞态。测试存储用纯标准库异步门闩串行事务，模拟 PostgreSQL 已存在的事务隔离；没有给合同层增加运行时依赖，也没有提高架构检查阈值。

## 验证入口

- `scripts/test-frozen-input.py`：相同模板数据库、实际基线/优化 API，准备至首个已保存批次之后的 RSS、数据库统计和完整逐接口等价。
- `scripts/test-frozen-recovery.py`：实际 v2/v3 保存与进程重启、全部实际模型输入对照、跨接口/多环境/长文档/任意精度数值、损坏注入、准备中断和停止。
- `scripts/test-frozen-storage.sh`：真实 PostgreSQL 所有权隔离、清单原子发布、复合外键、项目清空、旧数据升级。
- `scripts/test-frozen-browser.cjs`：隔离 Chrome 中查看 v3 观测值、复制完整 JSON 和真实样本来源。
