# MCP 数据库检索与按需读取

2026-10-14；性能计划第六步。11 个 MCP 工具和渐进式入口保持。

授权仍由 Navigation 在调用读取端口前执行。精确 ID 的跨项目/别名检查使用 identity，不为检查归属先加载原始样本。Observe 提供项目接口元数据；目录、环境、接口废弃和 method/business_scope 仍用现有规则确定有序范围。KnowledgeSearch 在此范围及 project_id 双重约束内检索自身表，不跨模块 JOIN。

PostgreSQL 在同一只读快照中完成字段/接口文字匹配、计数、稳定排序、版本摘要及分页；应用仅构造当页卡片。每个词做包含匹配，%/_/反斜杠不作为通配符。UTF-8 + ICU root collation 提供 Unicode 小写；SQL_ASCII 或没有 ICU 的旧数据库复用同一查询合同的内存参考实现，保持可读，但不承诺本步数据库下推收益。目录废弃的成员语义和字段 key/后代前缀由既有生命周期合同编译，不新建业务分类。

续页仍返回 revision 和完整 next.arguments；版本覆盖有序结果、目录/接口身份、环境集合和生命周期，剔除实时 calls/last_seen 等计数。版本摘要算法改变后，跨后端更新的旧续页可能要求从头读取。基于现有多个模块读取端口的快照边界保持，并未引入跨模块分布式事务。

精确字段用 Observe.field 复用原始结构恢复和 facts 规则；只计算请求字段，不读取全部保留代表样本。FieldKnowledge 明确只含该字段的规范 key/旧 key 说明与接口关系，与完整 EndpointKnowledge 分开。旧 key 与规范 key 的优先顺序保持。

新格式归档继续校验 manifest、每个实际读取块的长度/SHA-256、端点归属和指针。先选字段及可选 value_id，再读取相关文档块；无关块不读取、不校验。全归档发布校验仍走完整 read_values，不因按需读取放宽发布要求。

旧格式无 NUL 的归档通过 PostgreSQL JSON（非 JSONB）提取字段/文档，保留数字文本。旧文本中若有转义 NUL，PostgreSQL 的 JSON 提取也不支持，故退回已有完整文本解码路径；没有删字符、改 JSON 值或迁移旧档案。字段页仍需读取该字段所有相关文档以核对环境/来源计数；精确 value_id 只取其相关文档。单个相关文档本身很大时仍需完整读取并校验，未声称能按任意 JSON 子值切片校验。

采集 503 修复单独位于 intake 的正文解码边界：utf8 正文含 NUL 时，以既有 Binary 字节表示保存收到的 UTF-8 内容；普通 JSON/文本与 base64 路径保持。full/truncated/partial 和原长度/说明不变。只能保留收到的字节，不能恢复客户端已用替换字符解码丢失的上游二进制字节。批次失败、确认、同批重试和 sink 幂等语义不变。
