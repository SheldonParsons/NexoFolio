# 观测建档阶段验收记录

日期：2026-09-14。范围为pending观测建档、当前环境定义、差异保存和查询，不包括裁决、自动分类或目录重构。

## 已实现

- 持久worker领取pending观测，按项目/环境/接口顺序处理。
- 首次观测为该环境创建observed定义，接口身份在项目内稳定；全部标记unclassified。
- 相同提取定义附加原样例关联；不同定义创建/关联待处理差异，不覆盖当前定义。
- 文档、差异、观测关联和completed状态在同一事务提交。
- 120秒租约、执行代次隔离、90秒执行截止、有限退避重试；失败记录保留原因，CLI可重新排队。
- 四个HTTP读取接口和独立机器契约；项目权限在每次读取时检查。

## 测试

- 26个常规Rust测试通过，格式和严格clippy通过。
- 5个真实PostgreSQL集成用例通过；新增processing用例使用独立schema，不干扰其他测试的pending队列。
- 提取器验证JSON字段类型、值变化不改结构、空数组/null/截断/无效JSON限制、无required或业务解释推断。
- 同一接口跨环境各建基线；后续差异不改当前指针；重复差异合并但样例来源逐条保留。
- 同一环境接口顺序不被其他worker越过；过期租约重新领取后旧代次不能写成功或失败状态。
- 注入事务写入错误后无半份文档；五次失败保留failed，后续同键记录等待，手动重试后恢复。
- 真实HTTP上传 → 后台worker → 接口列表/详情/原始观测查询闭环通过。
- 列表、详情、观测列表和详情实际响应通过contracts/documents/responses.schema.json校验。
- 401/403/404、环境隔离、列表不嵌入大正文、原始Authorization合成值保留均验证。
