# 项目＋环境去重范围修正

用户明确的绑定流程：选择采集范围 domain＋path → 选择 NexoFolio 项目 → 加载该项目环境 → 选择或新建环境 → 保存绑定。接口服务标识不属于用户模型或判重维度。

## 后端变更

- v2批次删除service_key，仍要求project_id与environment{id或name}。
- v1接收仅保留旧队列原请求校验与幂等摘要，旧service值不再参与去重分区。
- 当前比较键为project_id＋environment_id＋接口方法/路径；结构摘要判断同一接口是否有变化。
- 新增迁移004，按最新已接收观测合并旧service分区的current heads，保留全部inbox、receipts；旧service值只留在原观测来源字段。
- 原v1契约保存在legacy/v1；根目录契约更新为2.0.0。能力声明支持1和2，回执回显输入schema_version。
- 无需清空用户数据、重建项目或重新签发内部Token。

- 格式、严格clippy、22个常规测试通过。
- 4个真实数据库测试通过：登录/项目、批量接收/环境、迁移、数据库连通。
- 接收测试新增v1标签a/b均在同一环境内去重、v1回执重放、v2携带service_key拒绝。

插件交互由插件任务独立实施；真实扩展界面的重载结果不由后端测试代替。
