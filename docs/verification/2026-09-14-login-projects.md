# 登录和项目实现验收

日期：2026-09-14。结构化结果见[脱敏证据](2026-09-14-login-projects.json)。

## 交付

- 新增 POST /v1/auth/login、GET /v1/auth/me、GET /v1/projects、GET /v1/projects/{project_id}。
- 禅道 REST v1 认证与用户身份读取；账号映射使用实例和外部用户 ID。
- 内部 Token 有效期为 3 个自然月，未过期时原样复用、不延期；并发登录受用户行锁保护。
- 超级密码使用部署配置的 Argon2id 哈希，登录已有用户，不请求禅道、不增加权限。
- 每次普通登录成功后完整分页同步项目；只新建 doing 项目，已有项目更新状态，不删除。
- 项目列表显示本实例的项目基础信息；项目详情检查本地权限，未授权返回 403。
- 普通业务只查本地 Token 和权限；没有隐式禅道刷新、独立同步接口或裁决功能。

## 自动化验证

格式检查、严格 clippy 和 workspace 测试通过：18 个常规测试，2 个真实数据库测试显式运行通过。
新增 access_flow 使用真实 PostgreSQL、真实 HTTP，以及可控的禅道测试服务，覆盖：

1. 首次登录与大小写账号映射、重复登录和并发登录复用 Token。
2. 原到期时间保持不变、三自然月有效期、到期后换新、旧 Token 被拒绝。
3. 登录凭证错误时不能因已有内部 Token 而跳过禅道验证。
4. 超级密码不请求禅道、不创建未知用户、不刷新项目权限。
5. 仅新建进行中项目、关闭后保留项目和状态。
6. 两个测试用户都能看到项目卡片，但只能读取有权限项目详情。
7. 第二页同步失败不提交部分数据和权限；完整空快照移除个人访问关系但保留共享项目。
8. 旧同步代次被拒绝，不能覆盖新授权。
9. 禅道停机后已签发内部 Token 仍可访问本地用户和项目；本地用户禁用后拒绝访问。
10. 内部 Token 不能访问 MCP；Token 密文绑定用户身份，篡改和错误密钥无法解密。

## 真实禅道端到端

使用用户指定文件中的账号，通过实际 Rust API 调用目标禅道；数据写入独立验收数据库，没有修改禅道用户、项目或权限。

- 首次登录 HTTP 200，读取 10 个可见项目，仅新建 2 个进行中项目，跳过其他 8 个。
- 再次登录 HTTP 200，Token 值及到期时间不变；新增 0 个，更新已有 2 个，跳过 8 个。
- 项目列表返回 2 个可进入项目，详情读取成功。
- API 正常停止、重启后，原内部 Token 继续读取用户和项目。
- 密码、完整 Token、无关个人资料未进入证据文件。

此处真实禅道使用一个账号；跨用户拒绝行为由受控测试覆盖，不宣称已完成禅道真实多账号 ACL 验收。
