# 空数组方向比较验证

本轮修改接收去重及后续观测文档比较，不调整前端，不实现裁决或目录重构。

规则：字段 `items` 始终保留；`[]` 只证明数组类型，不能证明元素字段消失。已知元素结构能够覆盖后续空数组，反向不能覆盖。比较仍检查其他字段、类型及请求/响应元信息；解析超限的 unknown 不能作为空数组证据。

接收侧使用 http-structure-2 及当前头结构投影，忽略弱样例时不替换当前头。旧头在事务和原有锁内，从当前原始观测按需升级，不扫描历史；旧记录重试仍返回原回执。处理侧共用 contracts 的方向比较，已入队的弱样例关联为 unchanged，原始样例及当前定义保留。

验证结果：

- workspace 31 项常规测试通过；5 项需要数据库的测试另在临时 PostgreSQL 中明确执行并通过。
- 格式、Clippy、合同生成一致性检查及2项 Python 合同测试通过。
- 新用例覆盖有值→空、空→有值、空数组旁新增字段、同批及重新加载时不降级当前头、旧头升级、原始回执重放，以及已有队列在 worker 中的相同行为。
- 解析预算边界补充后，knowledge 的4项测试及完整 Clippy 再次通过。
- 本地数据只读复核：31份当前定义、77条已完成观测，无漏关联或字段/类型核对错误。直接调用新 Rust 比较函数检查已有1处待确认差异，结果为已有定义覆盖该差异。历史差异状态没有自动修改。
