# 阶段4执行器修复与验收

日期：2026-09-16。对应[首轮问题清单](../audits/2026-09-16-stage4-model-tests-and-plan.md)。本轮修改后端审阅传输、全局汇总和预算预检；不修改采集、结构裁决、证据提取、前端、插件或发布合同。

## 1. 已修复什么

### 审阅输入的重复内容

接口/环境/修订或观测来源通过共享引用表表示；祖先结构通过字段ID查找；每个字段保留原路径、结构片段、证据提示、已有注释和是否可写。模型输入可以完整展开成原始ReviewSegment，所有正式及未采用观测字段均保留。

分片按模型适配器实际生成的请求JSON检查大小，包括提示和响应Schema，不再直接把配置的一半当作可用片段空间。继续采用保守UTF-8字节上界，没有盲目扩大token换算系数。每片最多48个单元，为逐项输出保留空间。字段切分时单独累计结构原子大小，去掉逐个原子反复序列化不断增长字段的做法。

### 重复的全事实汇总

5,817条事实仍完整保存在快照和机械索引中。全局汇总改为目录指标、全部接口导航、证据类型计数和每段审阅发现；不再把全部事实原文及所有普通keep意见重复发送给汇总模型。

逐字段意见和证据引用没有删除，保存在原审阅检查点中。顺带修复了审阅检查点回读只返回unit ID、遗漏review内容的问题；较大的导航资料按JSON指针分页，仍可完整追溯。摘要不能作为独立证据，修改目标和支持依据仍需回读原件。

### 预算预检与重试边界

开始前保存 `execution-budget` 检查点，计入：审阅次数、按有界摘要计算的多层汇总上界、16次规划/回读余量、重试余量。执行审阅期间继续保留后续工作所需额度。预算不足仍使用既有明确错误，不先花完审阅费用再发现无法规划。

汇总执行与预算估计复用同一分片函数。审阅发现摘要的序列化JSON字符串最多512字节；汇总摘要也按序列化字节检查，防止转义字符使估计失真。该限制不删除完整字段意见。

规划/回读的次数取决于模型选择，因此余量不是“保证一次完成任意修改”的承诺。所有实际调用仍受任务总上限和单次超时保护。

### 提示与兼容边界

提示明确共享引用的展开规则，区分“没有观察到结构”和“实际观察到JSON null”，不把翻译字段名、复述类型或ID样例当成有价值的修改。

上传、快照、候选、发布的外部Schema未改变，无需插件或前端同步。内部引擎/提示版本已变更；旧未完成任务沿用 `MODEL_CONFIGURATION_CHANGED` 保护，需要新建任务，不能混用旧分片检查点。历史候选和已发布文档不重写。

同一原始快照的模型传输体总量约3,155,760字节；这是共享表示的序列化大小，不是供应商token数。首次实验的7,271,820字节统计的是原unit数组，外层口径不同，不能直接当作同口径token降幅。

## 3.1 真实供应商试跑结果

修正后的试跑读取生产单次超时240秒，整轮执行器限时480秒。实际发起7次请求，6次完整返回，完成6/129段、61/2,536字段；第7次在整轮时间到达后中断，任务以TRIAL_WALL_TIME_LIMIT结束并保留检查点，没有生成候选，也没有发布。

前6次耗时分别为126.55、23.68、104.73、28.10、53.92、89.69秒，全部通过逐单元覆盖和快照引用校验。供应商对这6次报告总计75,219 tokens；未完成请求没有usage，不能把这个数当成试跑完整计费量。原样请求和解析后的输出保存在本地call文件中。

必须记录一次实验失误：最初脚本硬编码120秒，低于生产的240秒；这轮产生了3条调用记录，其中2次超时、1次在执行被停止后未保存完整结果，没有已通过的审阅，也没有可报告usage。发现后阻止该执行继续重试，并修复脚本读取生产配置，再额外进行上述一轮。没有提高生产调用上限或反复调prompt。生产条件下第一段126.55秒成功，证明原先的120秒试验条件过紧。

语义检查仍发现低价值审阅意见，例如建议将普通HTTP Accept头的已观察值记为不完整枚举。它只是审阅建议，尚未成为最终方案，不能据此宣称发布了错误枚举；也不能声称提示更新已消灭此类问题。全局规划是否舍弃它，需要完整候选试验验证。

结论：新输入格式、覆盖和执行预算机制得到验证；全量真实运行的耗时以及最终文档收益尚未通过验收。不按这6段线性推算整轮费用或时间，不将受控keep候选当作真实业务成果。阶段4仍未完成，下一步应处理实际执行耗时并验证完整候选，再进入阶段5文档拼装。
