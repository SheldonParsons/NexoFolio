# 四类字段补齐与完整观测值

用户授权：将请求 Header、请求体、响应体、响应 Header 的名称、说明和观测值统一处理。使用现有 checkout，保留其他未提交及并行修改；不创建子代理/worktree，不提交、不推送，不做 UI/浏览器测试，不启动真实模型整理。

## 完成条件

- 名称与说明分别记录 missing / filled / uncertain。漏返回、空白或通用占位词不能作为已补齐；名称或说明类型错误也不会让其他已校验字段作废。
- 明确无法确认时，保留具体原因及 uncertain 状态，不强行编造、不无限重试。完成校验与知识确认分开：已填的基础推断仍是 candidate，不会升级为已确认事实。
- 同输入下已经保存的有效名称/说明保持不变。收到保存 ACK 后，worker 才把该部分带入下一次请求；模型只被要求补缺少的部分。
- 按字段身份统计保存数量，部分写入、补齐写入不会重复计数。进度新增已补齐、待确认/待采集、待补跑，保留原有调用、重试及持久化指标。
- 人工字段仍受保护；人工字段本身有缺项时列为待确认，不由模型静默覆盖。

## 值事实与模型预算分离

新增 `FieldValueArchive`：每份已保留资料只保存一份规范化值文档，各字段按文档 ID 与 JSON Pointer 引用它。完整对象、数组和长字符串不会重复复制到每个字段/模型批次。值按类型、内容及表示形式去重，保留全部出现位置、样本身份、环境、来源与时间；值不是模型生成的。

完整存储不再受旧的 12 个值 / 80 字符限制。包含 null、空字符串、0、false、{}、[]、长值、超过 4096 行的数组。1 与 "1" 保持区别。大整数与高精度小数保留原有数字精度；完整值通过 JSON 文本读取和复制，避免浏览器先解析为 Number 再序列化造成舍入。

Header 名称的结构身份仍不区分大小写，原始名称/值和重复项保留。请求和响应 Body 的根值及子字段独立提取。URL 编码表单保留重复参数；multipart 摘要保留文字值和文件元数据，原摘要中的其他内容也不会被删除。没有采集文件字节就不声称存在文件内容。未发送、不可读取、截断和无法解析结构分别记为状态，不替换成 null、空对象或“字段不存在”。

完整值文档在首次模型调用前写入知识模块拥有的独立不可变归档表，随候选保留，应用后正式字段继续引用；观察样本后续轮换不会抹掉该轮已经保存的值。归档不混入每个模型批次，也不反复塞进进度响应。

模型仅使用预算内的代表内容和来源引用；大值不整体送入模型。字段新鲜度包含完整观测集合的哈希，不依赖值预览；快照序列化或数值预览表示变化不会使已接受字段重复补跑。短值信号和模型选项仍是解释预算，不再被当成完整观测值数据库。

## 页面与 MCP

- 字段页保持请求 Header → 请求体 → 响应体 → 响应 Header 顺序。
- 不恢复被用户移除的大“请求资料”原文区。字段详情按需分页读取完整值目录，展示类型、值摘要、采集状态和来源，可复制完整值并跳到真实样本。
- 候选尚未完成模型解释时，也能读取已经归档的值事实；缺少名称/说明明确显示待补齐或待确认。
- 新增只读 `read_field_values`，字段引用由 `knowledge.context.observations.archive_id` 和字段 key 定位；支持环境过滤、值目录分页和完整值分块读取。缺口和总数明确返回，不把摘要当完整原文，也不把历史认证当成当前有效凭据。
- HTTP/MCP 均校验项目访问，归档读取按项目和接口字段定位。不会调用真实业务接口。

## 验证证据

- 四类值提取测试覆盖大小写 Header、重复值来源、null/空串/0/false/空容器、长值、5001 行数组、JSON Pointer 转义、普通表单、multipart 文件元数据和精确大数。
- 模拟模型先只返回说明，再只补名称：第一次缺项已持久化，第二次请求只包含缺少名称，已保存说明未被模型另一份说明覆盖，字段计数最终为 1。
- 显式未知有理由时进入待确认；空名称、空说明、通用占位名称和匹配哈希却缺名称的字段仍为待补齐。
- 值归档覆盖幂等冻结、禁止替换、应用后读取、跨项目拒绝、环境过滤、超过一页及精确大数；隔离 PostgreSQL 执行真实迁移与存储测试。
- MCP 读取长值经过多个片段后可以还原原值；前端复制逻辑保留 JSON 文本，不做数值往返转换。
- Rust 工作区测试、严格 Clippy、架构限制、前端逻辑测试/类型检查/构建用于验证；没有真实模型质量/耗时或 UI 验收结论。

## 兼容边界

旧字段说明仍可读，旧值列表只作为历史摘要。新的完整性规则使用新版本冻结输入；缺少相应快照的旧轮次不会被当成相同范围静默续跑，会明确要求新轮次。当前项目此前已按用户要求清空整理内容，不会恢复旧名称、旧字段说明或旧候选。

完整性范围是“当前已经保留的采集资料”。此前没有保存、已经丢弃、读取失败或截断之后的内容无法凭空恢复，仍需补充采集。模型有了格式完整的答案不等于业务含义已被验证，待确认项需要后续证据或人工核对。

最终验证：Rust 工作区 230 项通过、28 项默认忽略；隔离 PostgreSQL 15 项通过；前端 219 项逻辑测试通过，类型检查与构建通过。严格 Clippy 和架构检查通过。新迁移已应用，本地后端沿用原配置重启，健康检查均为 200。最终只读核查当前项目仍有 63 个原始接口、91 份样本，接口说明/字段说明/候选/值归档均为 0，没有进行中的整理，未产生真实模型费用。独立测试库和私有临时配置文件已清理。
