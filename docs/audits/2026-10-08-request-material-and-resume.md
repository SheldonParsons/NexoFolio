## 请求事实与共享契约

`crates/contracts/src/request.rs` 定义 RequestMaterial，正式详情、候选文档和 MCP 使用同一事实模型：原始观察记录身份、样本 ID、环境、时间、来源、方法、完整 URL/query、请求 Header、正文状态/格式/内容/JSON 根值和根类型、响应状态/Header、认证观测及缺口。

- 请求和响应 Header 加入 FieldLocation。结构名称大小写不敏感；原始名称、值、顺序和重复项仍在请求资料中。观测出现不升级为必填，required 仍需声明等证据。
- 保留 none、full、partial、unreadable、truncated 的区别。完整 `{}`、空数组、JSON 标量和 null 有根节点；不依据 POST 等方法推断正文。
- `partial` 表示可用摘要，不能证明其他字段不存在。Fetcher 保留 multipart 文字及文件名称/类型/大小，不采集文件字节；摘要在 UTF-8 限额内保持合法 JSON。普通流读取失败但有可信前段时保留为 truncated。
- 采集能力仍是页面显式/可见信息，Header 为 partial；没有新增网络权限或 debugger，不声称已捕获浏览器自动 Cookie/Set-Cookie。
- 旧结构在读取时从保留的原始观察重新投影 Header 和根值；重复读取不改原文、ID 或计数。新采集与旧结构等价时复用旧指纹身份，避免仅因升级重复拆分结构。
- collect 合约包升级为 1.1.0，http_exchange 记录仍为 version 1。后端 schema、Fetcher 校验器、前端工作台及下载包已同步；已有序列化队列不改写。

## 原文、代表样本与增量证据

正式/候选请求资料和样本查看、差异、复制不再统一隐藏凭据。MCP 也不再对整个结果做 blanket redaction。产品按项目权限返回原文；开发日志、错误输出及审计不应承载这些原文。

结构计数与值证据分离：按实际 HTTP 值及有意义页面范围生成值身份，忽略批次 ID、序号和时间等运输差异；重复内容不增加代表份数，新值发布 EvidenceChanged 并进入整理输入。旧首份样本继续保留，额外代表样本最多 15 份，常规按约 8 MiB 目标淘汰较早额外样本；单份过大时仍受录入记录大小限制。接口合并按稳定身份去重并保持有界。历史调用数不等于保留原文数，旧引用超出保留集合时不能假装仍有原文。

模型输入仍有范围和预算：有界标量/来源/关联、24 字段与约 16000 字节自适应批次，过大单字段独占一批；不把全部原文直接送给模型。超过标量预算的 Header 值保留原文引用，也能因新增证据使解释失效，不把截短值当成真实取值。新证据进入后续整理及审阅流程，不自动修改正式知识。

## MCP 读取与认证

实际工具为 search_interfaces、read_interface、read_request_material、trace_dependencies。read_interface 提供地址、字段、关系及请求资料引用；read_request_material 按最多 16384 字符返回 JSON 文本块，客户端按 next_offset 与 source_record 续读，直到 has_more=false，再拼接解析。来源记录改变时拒绝混拼。大小限制不再导致大请求永久无法读取。

历史认证与当前可用凭据分开：提供观察到的载体、方案和来源，但 current_validity 为未知，未证实的 required/acquisition_source 不编造。没有虚构登录链。业务凭据与 NexoFolio MCP 访问 Token 明确分开，工具本身不执行业务 HTTP。

## 自动补齐、恢复与取消

- 缺失回复先保存合法字段，后续仅请求缺失项；超时/格式错误逐步拆小，反复失败回退单字段；429 退避，408 作为临时超时，其他永久 4xx 配置拒绝停止。
- 每批每字段最多 4 次尝试，单批最多 32 次调用或 15 分钟；字段收尾按已确认持久化结果再查覆盖，并最多做两次缺口补跑。接口说明/目录临时失败最多三次检查，复用已有结果。每次执行总预算 2 小时。持续失败或预算耗尽明确保留 partial；不会无限调用。
- 仍由串行保存接收器写入，保存和 checkpoint ACK 后推进。保留公平批次调度及模型服务共享并发预算，没有另建绕过并发限制的重试通道。
- 专用 `/curate/candidates/{id}/resume` 恢复原候选；`/cancel` 停止本轮。恢复保留候选 ID、创建时间、已保存批次和累计字段计数，记录执行尝试；本次执行耗时与原轮次开始时间分开。
- 新轮次在首次模型调用前冻结 PreparedProject；恢复复用冻结资料。旧轮次只在已接受字段哈希和旧总量/缺口均相容时冻结原范围。新 Header/根字段不会借旧轮恢复偷偷加入全量任务；请求资料仍可查看。
- 正式知识/人工修改/接口集合偏离基线时拒绝静默恢复；已应用、已废弃和已完成候选不能补写。项目事务锁、120 秒租约、20 秒心跳和执行身份隔离，防止双 worker 与旧 worker 迟到写入；进度 GET 不会把其他实例的运行任务误标成中断。
- 崩溃后从持久化命令重算已保存字段，防止 ACK 与进度保存之间的窗口造成重复计数；已保存目录也会复用。取消会关闭候选写入权并中止等待/重试。

前端分别提供“补齐本轮缺口”“查看本轮进度”“开始新一轮整理”；补齐入口不经过新轮次弹窗。当前技术栈和黑白紧凑样式保留。
