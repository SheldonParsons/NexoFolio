# 机制合并证明与实施

> 本文是收敛前的阶段性分析。用户随后明确要求单一生成入口；旧生成器及CLI已退役，仅保留历史读取/激活。现行行为以[统一重构](../architecture/0003-current-reconstruction.md)为准，不再将旧CLI视为需要保留的生成路径。

基线为`402b2aa8f45cf47839bfc24d9c5b096806e8ac4a`。先以当前调用链和现有行为约束判断能否合并，再用同一组回归验证重构前后。这里的“证明”是明确的状态/输入输出等价约束和可执行反例，不是宣称数学证明所有LLM判断正确。

## 决策与边界（实施前固定）

| 机制 | 能否合并 | 代码依据与必须保持的反例 |
|---|---|---|
| 旧目录与统一知识的版本激活 | 合并事务执行机制 | 四条写路径都鉴权、锁project_catalogs、先查回执、检查generation、切换版本并写回执。旧目录restore不能撤回语义；统一restore必须恢复两层。用意图区分目标，不需要两套事务状态机。 |
| 两类发布回执 | 保留协议适配 | 旧表以project+request为幂等范围，还检查actor；新表以project+actor+request为范围。旧回执和返回JSON不可改写。共用回执处理顺序，保留两种查询/编码规则。 |
| 目录版本与节点/归属落库 | 合并 | 两条发布路径都写catalog_versions及同样的子表。旧候选使用既有candidate_id且允许再次激活；新维护使用新版本ID。共同落库函数保留版本来源、重复激活和事务回滚。 |
| 旧候选校验与统一候选校验 | 保留各自校验，再进入同一激活器 | 旧目录候选允许快照后新接口/观测继续存在；统一语义修改要校验字段修订与全量覆盖。强行共用“宽松校验”会让过期描述发布；强行共用“严格校验”会改变旧目录操作。 |
| 小型原文回读与下一次规划 | 合并模型调用 | 只要原文/反例完整进入成功的规划调用，且缺读时不能发布，不必先独立调用模型写一段回读摘要。失败调用不得写完成标记。实际原文、请求审计与覆盖清单保留。 |
| 超大原文分片、图片读取 | 保留特殊读取路径 | 超预算内容不能塞进同一规划请求；图片未实际成功解读不能标为已读。不能靠丢弃这些情况减少代码。 |
| 全量审阅、覆盖校验、固定快照、受控原文来源 | 必须保留 | 持续录制期间任务输入不可变；每字段必须有阅读记录；未知/跨项目引用必须拒绝。检索少数接口不能替代全量审阅。 |
| 结构去重与证据处理 | 必须分开 | 同结构的新枚举/标签/关系仍要处理；旧记录重试不刷支持次数。两者共用身份/当前结构读取，但不能把证据生命周期折进“重复直接忽略”。 |
| 旧目录生成器与完整维护引擎 | 保留旧入口为兼容适配，不扩大 | 旧CLI/历史任务的输入输出是纯目录快照，完整维护包含全量字段和证据。旧目录任务不能悄悄启动语义维护；共用模型传输/目录校验，保留原合同，不在无迁移依据时重写历史任务表。 |

## 实施前验证

在未修改生产机制时，补充新旧回退并发竞争同一generation的用例：只有一条能成功；旧目录胜出保留语义，统一回退胜出恢复两层；成功请求可按原ID重放。原有失败回滚、跨项目拒绝、旧快照后新接口保留、回读失败不记完成等用例一起作为前后对照。

基线对照已通过，合并后相同数据库回归通过；随后已按用户要求完成唯一生成流程收敛。最终说明与验证见 docs/architecture/0003-current-reconstruction.md 和 docs/verification/2026-09-15-current-reconstruction.json。
