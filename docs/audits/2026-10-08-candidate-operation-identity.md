# 整理结果操作身份

整理结果页增加“操作记录”按钮，通过 Reka Popover 在按钮下方展示时间线：发起整理、补齐本轮、应用、废弃，记录实际发生的动作及执行者、时间。底部预留“系统”虚拟身份，不代表已触发自动执行。

身份采用 User / System / Unknown 三种类型。HTTP 用户动作只从已验证会话读取身份，保存当时的展示名称；不接受请求体指定操作者。系统身份可由未来内部自动化调用显式传入，不伪造真实用户账号。模型生成知识的 Author 仍是 Curate，与发起人分离。

候选 operations JSON 列记录成功生命周期事件。创建、补齐、应用、废弃与记录写入处于同一项目事务；应用/废弃幂等返回不新增或覆盖第一位操作者，失败应用不留下成功事件。新一轮不继承上一轮的操作人；同轮补齐保留原发起记录。

历史兼容：未保留发起人的旧候选显示未记录，不能推断为当前用户或系统。旧 reviewed_by 与终态可恢复已有应用/废弃身份，名称缺失时从访问模块的最小名称读取端口解析，标明来自现有资料。历史时间沿用原创建/更新时间并标记旧记录。此兼容投影不回写猜测的操作记录。

`GET .../curate/candidates/{id}/operations` 先验证项目访问权限，再读取该项目的轻量操作元数据；不加载整份候选文档/冻结样本。名称读取只处理已记录用户 ID，不返回账号、密码或头像大载荷。资料不可用时保留原身份记录并提示。

代码结构：创建与决定分别拆到 knowledge/core/candidates/create.rs 和 decisions.rs，HTTP 只负责认证、调度和显示兼容投影。新增知识模块迁移只添加 operations 列，保留旧数据。

验证：前端 15 项 Node 读取与审阅逻辑检查、类型检查和构建；核心操作身份/候选/续跑 10 项回归；后端 curation 范围 19 项回归（1 个显式只读诊断忽略）；隔离 PostgreSQL 操作身份与名称解析 2 项、候选生命周期及入口 3 项回归；10 项架构检查和严格 Clippy通过。测试数据库已删除，未写入真实项目，未启动真实模型整理或执行真实应用/废弃，未做 UI/浏览器测试。
