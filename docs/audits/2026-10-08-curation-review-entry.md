# 整理结果入口分流

点击正式文档中的“整理结果”或页头菜单中的同名入口，复用同一个只读控制器：

- 项目没有任何记录：保留“暂无整理结果，请先进行整理文档”提示。
- 项目有记录，但没有 ready / partial：打开整理结果列表。
- 项目有 ready（待审阅）或 partial（有缺口待审阅）：直接打开创建时间最新的一轮，并保留环境参数。

running、interrupted、applied、discarded 不作为待审阅项自动跳转；仍可在历史列表中选择。入口不执行整理、补跑、应用或废弃。

原列表只返回最近 30 轮，不能证明更早没有待审阅结果。新增 `GET .../curate/candidates?review_entry=true`，由知识存储在完整项目记录中选取最新待审阅项；没有待审阅项时返回最新历史摘要，没有任何记录时返回空数组。最多返回一条，项目授权和 no-store 保持生效。普通历史列表仍返回最近 30 轮。

前端保留重复点击合并、项目/环境/路由变化取消、忽略迟到响应、权限与读取失败提示。最新按创建时间决定，不使用更新时间，避免旧轮次续跑改变入口选择。

验证：

- 前端入口 10 项 Node 逻辑检查通过，覆盖空列表、仅历史记录、单个 ready / partial、多轮选择、环境保留、跨项目过滤、取消、失败和权限错误。
- 知识核心回归通过：60 条更新的已应用记录掩盖旧待审阅记录时，入口仍找到最新 partial；无待审阅时返回历史摘要；空项目返回空数组。
- 同一回归在临时隔离 PostgreSQL 数据库中通过，测试数据库随后删除；未写入真实项目。
- 后端 10 项架构检查、严格 Clippy、后端编译、前端类型检查和构建通过。
- 确认真实数据库没有运行中候选后，保留原配置重启本地后端；`/health/live` 与 `/health/ready` 均返回 200。
- 未执行 UI / 浏览器测试，未开启真实模型整理或改动候选审阅状态。
