由用户执行真实 Agent 测试。以下话术分轮发送，先开场，再分别测试。项目、环境、目录、接口和字段全部由实际 MCP 发现，不预填 UUID，不预设某个具体字段必然有资料。

## 测试前

将新版后端加载到待测试实例后，在 Codex 重新连接 MCP。先核对实际工具列表，应该是 11 个，并包含 browse_directory、read_response_material、read_source_evidence、inspect_knowledge_coverage。旧服务返回 7 个时，这轮新能力尚未加载，先解决服务版本；本地修改文档不会更新线上后端。

## 0. 开场

```text
请使用 NexoFolio MCP，对「商用订单管理系统」做只读接口知识检索测试。先列出实际工具并确认有目录探索、响应原文、来源证据和覆盖检查能力，再按项目名称发现项目，选择「测试环境」；名称不唯一或环境不存在时让我选择，不要让我提供 UUID。

检索路径由你根据任务决定，可以浏览目录、搜索、沿字段/接口关联跳转。每次只读取当前需要的范围，不预先下载全项目字段和样本。所有结论说明来源、环境、确认状态和未读范围。不发送业务 HTTP 请求，不启动整理或应用候选结果。
```

## 1. 陌生模块探索

```text
我还不知道这个系统的接口名称。请先浏览业务目录，用已有介绍给我一份简短业务地图；再选择与技术咨询相关的目录，解释它有哪些功能分组和主要接口。你自己决定深入哪些入口，不用展开全部字段和样本。最后列出你实际读取过的目录与接口，以及没有读取的范围。如果正式目录为空，继续找未分类或全部接口入口，别把空目录当成没有接口。
```

## 2. 字段关联找接口

```text
从刚才实际找到的接口中，选择一个字段说明提到了其他接口、或者已有相关接口证据的请求字段。完整读清该字段，找到它指向的接口，并核对那个接口的用途和相关返回字段。已有结构化引用就沿引用读取；只有文字说明就提取线索搜索核实。告诉我字段、来源接口、两边字段位置、依据和确认状态。多个候选请继续辨别，不能认定第一个匹配就是来源；资料不足时明确列出缺口。
```

如果实际没有这种字段，报告“本次数据未覆盖该场景”，不能编造关联或把它算作测试通过。

## 3. 字段反向搜索

```text
选择刚才真实读到的一个有中文名称或说明的字段，按该名称或说明反向搜索所属接口。列出命中的接口及字段位置，并核对是否与先前读取一致。不要逐个下载全项目样本。说明这个查询覆盖的是已保存字段知识，还是接口原始字段事实；空结果不能证明未整理字段不存在。
```

## 4. 请求与响应分开读取

```text
选择一个刚才找到的 POST 接口及测试环境里实际保留的样本。先只读取请求 Header，再按需要读取 URL/query 和请求体，说明正文是未发送、完整空对象、完整内容、部分摘要、截断还是不可读。再独立读取这个样本的响应 Header 和正文，并核对样本来源一致。不要根据 POST 猜测请求体，也不要把历史认证当成当前有效认证。只准备资料，不发送请求。
```

## 5. 长内容与证据续读

```text
从已经找到的样本或字段中选择一份确实需要多块读取的内容，用较小的块大小续读到完整，再给出结论。使用服务返回的下一跳，不猜偏移；只拼接同一版本的内容。随后读取它实际保留的页面/操作上下文或字段来源证据。说明哪些是观测、哪些是解释或待确认，哪些资料未保留。没有足够长的资料时如实说明本场景未覆盖。
```

## 6. 范围与缺口

```text
只检查刚才探索过的技术咨询相关目录或接口，分页列出已知资料缺口，选择最影响理解的几项说明。区分未分类、字段未解释、语义待确认和采集不完整。请报告这次检索覆盖了什么、还有什么未读或未采集，不要把没有已知问题说成业务知识完全正确。
```

- 是否不必要地读取全量字段/样本，是否漏掉未分类入口或续页。
- 每个任务的工具调用次数、耗时和客户端可见的上下文消耗；客户端未显示时记录未知。
