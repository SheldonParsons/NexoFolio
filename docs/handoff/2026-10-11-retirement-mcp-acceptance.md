# 新会话的逐步 MCP 验收话术

适用于新 Codex / GPT-6.1 Sol 会话。先由人在隔离合成项目的网页上准备目录、接口、字段与引用关系，再废弃/撤销；MCP 自身没有写工具。不能用真实业务项目做破坏性准备。

## 第一步：发现与基线

> 只依据本轮 NexoFolio MCP 返回验收。不要调用业务接口，不整理、不应用、不修改资料，不启动子代理。先 list_projects 找到我指定的合成验收项目，再 list_project_environments 确定环境。记录 11 个工具是否保持只读，以及项目生命周期版本、待核对提示和废弃数量。先确认连接的是已更新实例；工具参数或生命周期字段缺失时，记录为入口/版本未核实，不当作“没有废弃内容”。没有准备好的合成项目就报告缺口，不自行修改真实项目。

## 第二步：废弃后的下一次读取

> 我已在网页上废弃合成接口 A。请在同一项目/环境重新读取。用默认搜索找有效接口，再按返回的历史入口或 include_retired:true 找 A，并精确 read_interface A。确认 A 显示 retired，仍有历史详情入口；不要把它当成不存在。读取 A 的字段与一个原始请求/响应，分别报告生命周期状态、证据确认和原始材料，不能混为一谈。每一步只展开回答问题需要的内容。

## 第三步：引用与字段边界

> 合成接口 B 引用了 A，请读取 B 的 overview、relations 和必要的 source_evidence。确认 B 自身仍有效，已废弃来源有明确提示；默认有效关系与历史关系可区分。若有废弃字段，精确读取它及子字段，并对比请求/响应中同名字段、相邻路径，确认范围。不能从结构关联推断全部语义依赖，更不能执行业务调用验证。

## 第四步：目录与整理核对

> 我已废弃合成目录。请先读取默认目录和待分类入口，确认内部未废弃接口仍有效，并能在待分类中找到；不要只用全项目搜索掩盖目录导航缺口。再沿返回的目录历史入口，原样使用每一层 open/interfaces 的 tool 和 arguments 展开父目录、子目录及接口，确认历史范围没有在下一跳丢失，数量与实际返回一致。记录当前待重新核对提示。等我在网页按原入口开始新一轮、审阅并应用完整结果后，再读取：确认有效接口重新归属或待分类、旧目录可由历史入口读取、项目核对版本已推进。没有看到应用结果就不要宣称整理完成。

## 第五步：撤销与旧候选

> 我已在网页撤销一个直接废弃决定。重新读取项目版本与对象状态，确认版本递增、对象恢复有效且重新出现待核对提示。旧候选不能直接应用/续跑需要网页或 HTTP 测试证据，MCP 无写权限，不要伪装执行过。报告当前读取证据与仍需网页验证的项目，完成后停下。

## 最终输出要求

> 给出简短调用台账：工具名、对象、必要参数、返回状态和证据入口。把确认结果、仅见候选/关联线索、未知项分开。不要输出凭证、完整业务敏感样本，统计不知道就写未知。此次验收没有业务调用、资料整理或状态修改。
