# Observed documents 2.0.0

Internal Bearer authentication and local project access are required on all endpoints. No ZenTao request or token renewal occurs during reads. Lists never embed raw bodies. All data is observed/unclassified, not an adjudicated or business-confirmed contract.

GET /v1/projects/{project_id}/interfaces?environment_id=UUID&page=1&limit=20&query=optional -> InterfacePage. Environment is required; page1..100000, limit1..100. query is a case-insensitive literal substring of method or path, max500 UTF8 bytes, not semantic/full-text search. total is after filtering in that environment. Stable order method,path,id. No fake folder tree; classification is unclassified for every initial document.

GET /v1/projects/{project_id}/interfaces/{interface_id}?environment_id=UUID -> InterfaceDetail. Definition is the current observed baseline in that environment. The same project/method/path shares interface_id across environments, with a separate current revision per environment. origin_ingestion_id points to its original sample. created_at uses UTC RFC3339. A missing project/environment/interface relationship is404; unauthorized is403; missing permission snapshot503; invalid token401.

GET /v1/projects/{project_id}/interfaces/{interface_id}/observations?environment_id=UUID&page=1&limit=20 -> ObservationPage. Processed observation summaries with outcome and difference IDs. No raw payload here. More samples are fetched page by page.

GET /v1/projects/{project_id}/observations/{ingestion_id} -> ObservationDetail. Can be queried immediately after upload accepted to inspect pending/processing/completed/failed. Contains raw_record unredacted and may be up to the accepted single-record size. completed means this processor committed its result; difference_recorded means pending comparison, not approved or applied. proposed_definition is present only for a difference and does not replace current InterfaceDetail.definition. Compare it against the referenced current baseline; automatic adjudication and difference acceptance are absent.

Definition extraction records observed query parameter names/types, header names/types, media types, request/response JSON fields and actual types. Query values are strings. Body absence, capture failure/truncation, invalid JSON, null/empty arrays, non-JSON and extraction limits are explicit; none implies complete business knowledge. No required fields, Chinese meanings, enums or human assertions are inferred. Arrays include all distinct element shapes up to the versioned bounded extraction budget (observed-http-1 used10000 nodes; observed-http-2 uses100000 per body; depth64). Raw sample strings, headers and values are not redacted or replaced.

First observation in an environment creates an immutable baseline and current pointer. Later equivalent extracted definitions attach a sample with unchanged outcome. Non-duplicate or insufficient comparisons create/reuse pending comparison material with base revision and proposed definition; they NEVER overwrite the baseline. Future version handling needs a separate adjudication implementation. This worker does not update ingress dedup heads, invoke models, classify or rebuild directories.

Worker claims in received_at/id order per project/environment/interface, preserving order across concurrent workers. Claim lease120s, processing deadline90s, retry2/4/8/16 seconds, fail after5 attempts. A failed item blocks its same-key successors until repaired and explicitly retried; other keys continue. Old generation/expired owners cannot finish or report failure. Result tables and completed state commit atomically. Manual administration: nexofolio-admin process-one; nexofolio-admin retry-observation <ingestion_id> only retries failed items. No frontend retry/delete/adjudicate endpoint is exposed.

Configured worker (ZenTao base set, same as business API mode) polls PostgreSQL every idle second. An unconfigured foundation worker remains idle. Migration005 must run before starting the new worker. No in-memory queue claims to provide persistence; restart recovers outstanding claims when leases expire.

Comparison is directional: known array element schemas cover later empty arrays when all other fields and metadata remain covered. Such queued observations link as unchanged and preserve the baseline; first-empty then populated observations continue to a pending difference as newly observed information. Parsed null retains an observation shape but does not establish a business type. Null-to-concrete is enrichment; concrete-to-null is insufficient type evidence. Truncation, unreadable bodies and extraction gaps cannot prove repetition even when their partial representations are identical. Existing recorded differences are not automatically adjudicated or deleted. See the versioned assessment contract below for the precise processing result.

New template-identified observations create method/template identities and path parameters (in=path, neutral param1/param2 names, string URI values). Admission pins the identity; worker does not reinterpret with a newer project policy. Original URL/values remain in raw observations. Legacy documents, definitions and pending queue identities are not rewritten; old receipts are immutable. Different structures within one template remain pending differences, not overwritten definitions.

Classification now reflects the current official directory: classified when the active version assigns a business directory, unclassified otherwise (including its fixed system folder). Definition/revision/evidence remain independent of directory publication.

Package2.0.0 adds independent assessment reads and allows observed-http-1/observed-http-2 in definition.extractor_version. Existing response field layout and ingestion receipts remain unchanged. This is a document-reader contract upgrade: strict 1.x clients must sync the new bundle before a backend producing observed-http-2 is deployed; historical observed-http-1 remains valid.
GET /v1/projects/{project_id}/observations/{ingestion_id}/assessment -> assessment.schema.json (404 until structural processing completes).
GET /v1/projects/{project_id}/interfaces/{interface_id}/assessments?environment_id=UUID&page=1&limit=20 -> assessment-page.schema.json. Same project ACL and pagination as observations; keyword query is unsupported. Results are persisted processing-time assessments, never silently recomputed on read.

assessment=null means a historical row has not been classified under these rules. initial=true means no baseline was compared; it is not a duplicate. Otherwise categories can contain enrichment, difference and insufficient together, or duplicate alone. Findings include location, escaped field path (array item `*`), reason, prior and incoming observed fragments. A difference is an observed structural distinction, not approved contract change. Missing fields, null after a known type and unreadable/limited structure cannot prove deletion. Complete null observations retain a shape, allowing repeat filtering; null does not infer a required/nullable contract.

The incoming field is located by project/environment/interface + ingestion_id + location/path. base_revision_id identifies the comparison basis, NOT the adopted revision of newly observed fields. incoming_definition reuses the existing initial/proposed material when present; it is null for duplicate observations without a separately stored proposal. Fetch the original observation if raw material is required. extractor_version may be null for old unchanged rows whose incoming extractor was not recorded. Later consumers must keep unknown/unadopted fields separate from the current revision and retain source IDs.

observed-http-2 and http-structure-3 use the same bounded JSON shape extraction (100000 nodes per body, depth64), with scoped incomplete markers. Comparisons bound work and findings; limits produce insufficient findings, never a successful full-coverage claim. Legacy STRUCTURE_EXTRACTION_LIMIT remains insufficient even if incomplete schemas compare equal. Processing preserves existing created/unchanged/difference_recorded outcomes for compatibility: difference_recorded is the legacy pending-comparison bucket, whose precise nature comes from assessment. No baseline is automatically overwritten. Repetition still feeds new value/UI evidence independently.

Finding locations use request.query/path/header/body, response.header/body, response.status, request.media_type or response.media_type; interface/observation are whole-scope gaps. before/observed carry structural fragments or metadata scalars, not original payload examples. ObservationFieldRef also addresses observed metadata; it must not be cast into an adopted FieldRef. No finding proves that a field is required, deleted or that a new API version exists.

The assessment ingestion_id identifies the admitted structure material. A later capture whose structure was deduplicated may point to that ingestion but has its own capture observation ID and original values. Evidence consumers must retain that capture ID for value provenance; an assessment's source raw record must never substitute for a later observation's values. Listing assessments is bounded and paginated; consumers assembling an immutable snapshot must freeze the returned IDs/material rather than rereading a moving list during model review.

## Observed structure representation (2.1.0)

New observations use `observed-http-3` / `http-structure-4`; comparisons report `observed-comparison-2`. Array objects with identical field sets may share one field-level structure when differences are null/unknown observations or nested array observations. Concrete scalar type conflicts, different field sets, extraction gaps and unsupported schema constraints remain distinct. Null alternatives describe observed values, not a declared nullable contract. Empty arrays do not prove element deletion. Fields are not inferred required. Original samples preserve value combinations; field coverage does not assert that every combination was observed.

Legacy stored shapes are projected through the same compaction for comparison only. Their revision IDs, raw definitions, hashes, evidence references and old assessments are not rewritten. Current-head fingerprints upgrade under the existing lock from source observations. Existing stored documents continue to expose their immutable definitions; the new representation is used for new definitions.

## Compact read view for existing revisions (2.2.0)

Document detail and newly frozen maintenance interface definitions now use the shared compact field projection. If representation changes, optional `definition.schema_view="http-structure-4"` identifies the projection; `extractor_version`, revision ID, original stored definition and source hashes remain unchanged. The raw observation endpoint remains available via origin_ingestion_id. This does not adopt an interface change or assert joint value constraints. Old frozen candidates/snapshots remain unchanged. `observed-http-3` is an accepted extractor version in the public schema.
