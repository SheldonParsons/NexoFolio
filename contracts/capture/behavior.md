# Capture 3, package 1.2.0

POST /v1/ingestion/batches accepts schema_version=3 using batch.schema.json and per-record record.schema.json. HTTP payload_version=1 remains compatible with its existing payload. New kinds: page_context, interaction, ui_snapshot, image_reference (payload_version=1). Common context IDs are client UUIDs, event_seq is monotonic per frame/view, timing is Unix milliseconds. No user-operated recording session is introduced. Enhanced records require context; HTTP without context remains valid but cannot establish strong cross-request relations.

Discover enhanced support with GET /v1/ingestion/capabilities?schema_version=3. Default capability responses preserve the legacy shape so old installed clients remain usable. A server which returns only1/2 does not yet support enhanced upload; retain new-format records and do not rewrite old queued IDs/payloads. V3 response is receipt.schema.json. accepted means observation/evidence is durable, not a new interface; structure reports accepted/duplicate/not_applicable. Full retries replay the original receipt; conflicting reuse rejects. Historical v1/v2 receipts never change. New legacy HTTP observations feed evidence while their responses retain structural accepted/FORWARDED or ignored/DUPLICATE_CURRENT_STRUCTURE semantics. V3 is required to query independent observation receipts; historical receipt status and IDs never change.

HTTP, UI and asset references share project/environment binding. Capture scope/actor/producer ownership and IDs are immutable in the upload queue; no values or original URLs are redacted. Page bridge data is untrusted. Background owns identity binding and authentication, never page scripts. Retain queued records until matching receipts; storage/offline errors do not silently discard unacked data.

PUT /v1/projects/{project_id}/assets/{asset_id} uploads original image bytes (PNG/JPEG/WebP, max8MiB), Content-Type required; response asset.schema.json. Same project/asset ID and same bytes is replay; changed content409. GET same path returns authenticated image bytes, Cache-Control:no-store and nosniff. Upload assets before their image_reference record; preserve dependencies/retries. Assets and evidence never cross project ACL boundaries.

UiValue always includes state and value: present can contain null; omitted/unknown carry null. Do not guess API omission from a blank UI option; backend correlation records actual request omission separately. Options may be partial/virtualized: complete=false plus limitations. HTTP request_started_at_ms/response_completed_at_ms should reflect capture timings, not upload time. Missing or inconsistent times cannot imply causality.

Default capture: current authorized bound active page, independent of panel visibility. Route/page/meaningful click/change/submit stable ~500ms may collect local UI context; no per-keystroke upload or per-XHR screenshot. Images at most once/3s and10/min per active page, reuse equivalent page states. No debugger. One-time Chrome screenshot permission is requested in existing authorization flow; permission failure preserves HTTP/DOM and marks missing images. No model calls in capture or evidence extraction; models run only explicit reconstruction.

Capture interruption/capability gaps use page_context records with complete=false and limitations (e.g. CAPTURE_INTERRUPTED, FRAME_UNAVAILABLE, SCREENSHOT_PERMISSION_MISSING); keep the original context/page URL and minimal known title, empty regions/breadcrumbs if unavailable. Do not synthesize network completion. event_seq is per frame/view; allocate IDs before durable enqueue and preserve them through retry. Image dimensions are viewport CSS pixels and device_pixel_ratio; source image bytes remain original captured encoding. Unknown UiValue state is not an API omission.
