# Chrome minimal sampling profile 2

This client policy uses capture package 1.4.0, wire 3, payload 1. It does not add public fields or require other integrations to behave like Chrome.

- Users are not performing a scripted recording. Capture independent local facts during normal, interrupted and interleaved use; never invent a business session from neighboring events or a shared tab.
- Capture only the current authorized, project/environment-bound active page, independently of sidebar visibility. Existing request contexts and queued records retain original ownership after tab/route/binding changes. Logout/revocation stops new capture; retained queues are never uploaded as another identity.
- New screenshots and screenshot-only permission requests are disabled. Historical image records/assets and their upload dependencies remain valid. Do not revoke host permissions required for existing authorized HTTP capture.
- At initial page context and route changes, retain URL/title and known coverage gaps. Do not scan the whole document for breadcrumbs, business regions, table headings or arbitrary text.
- Observe meaningful click/change/submit events. Read the target label, role, actual value and selected/visible options. Do not upload each input keystroke; the final value is read on change or the later operation snapshot.
- At a button/query click or submit, synchronously freeze the associated form's visible controls during event capture, before application request handlers run. Prefer an actual/explicit form, including a uniquely associated form in the same dialog/drawer; otherwise inspect a bounded nearest component form or local field group. Limit ancestor search to six levels and exclude document/application roots; hidden/inactive forms and panels cannot establish ownership, and multiple independent visible owners fall back to the target with a coverage gap. A component class is a locality hint, not proof of business intent. Reuse this operation snapshot across its requests. HTTP hooks never traverse DOM.
- Bound local subtree traversal to 2000 nodes, output to 80 visible controls and 100 observed options, sampled strings to a shared 24576-character budget, and each snapshot payload to 128KiB; record truncation, virtualization, hidden options, inaccessible frames and unknown values. complete=false means partial observation. A selected option with a label is not evidence that the option list is exhaustive. Custom controls may expose data/ARIA values and visible labels; a display label alone must never be invented as an API enum value, and an empty-control placeholder is not a selected option. Preserve unknown values and partial coverage.
- An operation ID is available only for requests begun during the observed event dispatch. This is a conservative candidate association, not asynchronous causality tracking. Delayed/debounced/Promise-started requests may have no operation ID; declare that limitation. Do not rewrite application timers or Promises to manufacture attribution. Separate click and submit dispatches remain separate operations.
- Switching modules, tabs within a page or dialogs must not reuse another region's controls or cached options. Same-URL navigation does not prove a shared task. Do not retroactively attach A's late response to B or fabricate a new page view without an observed state change.
- Freeze a request's operation ID at request start. A later interaction or response must not change it. Periodic background traffic after the event ends must not inherit the last operation forever.
- Use the page's original observation timestamp for captured_at after validating it, not the background receive time. Do not wait for page stability and then backdate a snapshot to the click time.
- No independent sampling on scroll, resize, DOM mutation, or every XHR. No automatic page actions, new recording buttons, background LLM or frontend redesign.
- Keep durable batching, immutable retry IDs, capability negotiation and explicit pressure/offline reporting. The panel's 20-row display limit must not truncate the upload queue.

Acceptance probes exercise capture boundaries, not prescribed user workflows. Verify that an operation retains its own locally visible values/labels, including component forms, an external dialog footer and custom options; any backend mapping remains inferred. Test interruption A → B → late A response, same-URL tab/dialog switches, mixed polling and interleaved independent requests. Include same-valued controls, unrelated polling, asynchronous requests without association, late responses, sidebar closure, tab/binding switches, offline restart, old queue replay and revoked authorization. Mocked DOM/Chrome APIs prove only synthetic behavior; actual installed-extension recording is a separate user/authorized Chrome acceptance step.
