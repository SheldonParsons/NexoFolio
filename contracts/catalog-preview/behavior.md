# Catalog preview contract 1.3.1

Generation remains administrative-only; authenticated read-only HTTP preview is now available. Generation remains CLI-only. Authorized HTTP publication/restoration is available, with explicit generation and idempotency checks; no automatic activation or MCP writes.

A snapshot is project-wide and contains each observed interface once, with all its environment/current-revision definitions. It includes method, path, project/environment names and stored observed schemas; pending proposed definitions and raw traffic bodies are not added to the model input. Creation uses one repeatable-read transaction. Max 200 interfaces and 1 MiB serialized snapshot: exceeding either is an explicit error, never silent sampling. New interfaces after the snapshot remain outside this candidate and continue through ordinary ingestion.

The candidate contains UUID directory IDs and parent links, plus exactly one assignment per snapshot interface. A null directory_id explicitly means unclassified. Missing, unknown or duplicate interfaces, broken parents, cycles, duplicate sibling names, invalid text and unknown assignment targets reject the candidate. Depth above four and empty leaf directories are reported as warnings. Metrics describe the proposal; structural validity is not semantic correctness, approval, or publication.

Task states: pending -> running -> ready (structurally valid), rejected (inspectable invalid proposal), or failed (generation error). Ready/rejected tasks are immutable; create a new task to compare another proposal. Manual run can retry failed tasks or reclaim running tasks after their five-minute lease expires. Each claim increments a generation; old/expired execution cannot finish or fail a newer execution. Missing model configuration fails before claiming. A killed command can leave a running task until lease expiry. No automatic retry daemon is enabled. Commit failure rolls back candidate materialization; lease recovery remains available.

Stored metadata: snapshot timestamp/hash, contract version, candidate/task ID, generation, model/adapter/prompt version and exact system-prompt SHA256. Successful and rejected proposals retain model output and structural review. Only valid candidates materialize node/assignment rows. No canonical interface definitions, current revisions, adjudication state, or active directory are changed.

Model adapter: explicitly configured chat-completions-compatible base URL, model, key file. POST /chat/completions, non-streaming JSON-object response. Output must finish with stop and parse as this contract; provider errors/truncation/non-JSON/unknown fields fail explicitly. No production fake-success fallback. Request timeout 120 seconds, connect timeout 10 seconds, redirects disabled, candidate content max512KiB and response envelope max1MiB. Credentials/provider bodies are never logged. Captured/project data is untrusted input; it cannot direct tools, writes, or publication. Structured stored data is not automatically redacted.

Rust types in contracts are authoritative. Generated JSON schemas are compared with Rust in tests; the manifest hashes schemas, this behavior and the prompt. Contract changes require a version bump. CLI summaries expose task IDs/status/review; catalog-show exposes the full snapshot/proposal for local administrative inspection.

HTTP read-only views: GET /v1/projects/{project_id}/catalog-previews?page=1&limit=20 accepts optional status (pending/running/ready/rejected/failed), page1..100000 and limit1..100. Order snapshot_at DESC then task_id DESC, total respects status filter. Items omit full snapshots/proposals and expose task_id,candidate_id,status,snapshot_at,interface_count,directory_count/unclassified_count/structurally_valid (nullable before evaluation). GET /v1/projects/{project_id}/catalog-previews/{task_id} returns {published:boolean,task:PreviewTask}, where published means this candidate is the currently active version. This is project-scoped across environments; environment_id is not a query parameter. The snapshot's own environment/revision data is displayed, not silently replaced by live definitions.

Both require internal Bearer session authentication and project access. The reader independently checks enabled user, matching project instance, synced grants and current project permission under the user-row lock used for grant replacement. 401 invalid/disabled session, 403 denied project, 503 unavailable permission snapshot/database, 404 unknown project/task or task from another project. No task data leaks across project IDs. Cache-Control: no-store. Unknown/invalid list parameters are400; POST/PATCH/DELETE not supported. ready is structurally valid, not published; rejected may contain invalid tree references and clients must display issues or use safe flat rendering. UI generation/edit controls remain out of scope; publication/restoration require explicit user actions.

Candidate merge groups (optional for legacy candidates): representative_id must be a member; member_ids includes at least two distinct snapshot IDs; no overlap/unknown IDs. Members keep all original assignments and environment definitions and must share method and directory. path_template generalizes whole segments only and must cover every member with identical fixed segments/path depth. reason is mandatory. Invalid proposals reject the candidate. These are display groups only, never persisted canonical identity aliases or automatically learned ingestion rules. Existing candidate JSON without groups still reads. New snapshots may carry recognized_path hints. logical_interfaces reports the proposed displayed count; raw metrics/coverage still count all original IDs.

Official directory (1.3.1): every project has one permanent system node, named 待分类, system=true/locked=true, identified by unclassified_id. New interface documents lacking an active version assignment automatically belong there. System identity cannot be moved/deleted and candidate nodes cannot use its ID/name. Candidate publication copies an immutable directory version; current definitions and evidence are not overwritten. Merge groups remain display relationships, not physical interface merges.

GET /v1/projects/{id}/catalog returns OfficialCatalog. GET /catalog/interfaces optionally filters directory_id and expected_generation and accepts page/limit; results reference live per-environment revisions. GET /catalog/versions lists published versions newest first. No published version (version_id=null) is the initial all-unclassified view and is always restorable. Missing/invalid directories404; stale read generation409.

POST /catalog/publish requires PublishCatalog; POST /catalog/restore requires RestoreCatalog, including explicit version_id:null for initial state. All project-authorized logged-in users can perform these operations (same permission boundary as environment management). Auth is rechecked transactionally. expected_generation must match the locked current state; stale writes409. request_id and exact body identify a user-scoped receipt; identical retries replay the original result without another activation, conflicting reuse409. Client must GET current after success/replay. No-op activation keeps generation unchanged. Versions and original candidates remain available for rollback. Only structurally valid ready candidates from the path project can publish; all referenced interfaces must still belong to it. New interfaces outside the snapshot remain in the system directory. The fixed system node always survives publication and rollback. No directory rename/move/delete endpoints are introduced.
