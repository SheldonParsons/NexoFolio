# Knowledge maintenance 2.0.0

Only explicit reconstruction starts model work. POST /v1/projects/{project_id}/maintenance-runs with {request_id} creates a durable immutable snapshot and pending task; repeats return the same task. GET same collection?page=&limit= and GET /maintenance-runs/{run_id} expose status/coverage/candidate. GET /maintenance-runs/{run_id}/snapshot returns its revision-bound source. No UI mount or read endpoint starts a task. Pending evidence is counted but never falsely claimed as reviewed. Current captured data continues independently.

GET /v1/projects/{project_id}/interfaces/{interface_id}/knowledge?environment_id= returns independently published semantic annotations and their definition basis. Stale annotations remain explicitly marked when basis revisions differ. Descriptions, parameter relations, and enum entries are structured with evidence refs and verification observed/inferred/needs_review. Publication is approval, not proof. Raw schemas and evidence are not overwritten by text maintenance. Omitted/present-null are distinct. Closed enums require declared complete-range evidence; observed samples alone cannot establish complete=true.

POST /maintenance-runs/{run_id}/publish {request_id,expected_generation} atomically activates the candidate directory and semantic annotations. Only ready, complete-coverage, validated candidates can publish; generation and all snapshot definition bases must still match. Unknown references, reserved fixed directory edits, cross-project facts or incomplete reads are rejected. GET /knowledge/versions lists releases; POST /knowledge/restore {version_id:null|uuid,request_id,expected_generation} restores directory and semantics together (null resets both to initial). Old catalog-only endpoints remain compatible and preserve active semantic annotations. Same request ID/body replays its original receipt, conflicting reuse409; clients GET current after success. No automatic publication.

All reads/writes require internal Bearer and current project access. Snapshot field IDs are immutable within the run and map to EvidenceFieldRef: either an adopted FieldRef or a read-only ObservationFieldRef. All fields must receive a review; oversized interfaces split by schema nodes with child references. Global planning sees directory/global index plus hierarchical review summaries; summaries never replace the pinned original. Controlled read requests support field, interface, fact, directory, image, annotation, summary, observation and source references only; no arbitrary files, SQL, network or publishing tools. Required target/evidence readbacks are enforced before candidate completion. Missing capacity/vision/context data produces explicit incomplete/failed status; no silent top-k fallback.

Run statuses pending/running/ready/incomplete/failed and phase identify progress. Model calls run with per-call timeout, renew execution lease and persist checkpoints. Old executions cannot save or publish. Strategy keep/insert/partial/full is selected by the planner; the caller does not choose scope. Candidate actions are applied to the pinned baseline and mechanically validated before release. Existing model descriptions do not count as new independent evidence.

GET /maintenance-runs/{run_id}/checkpoints?page=&limit= returns the real stored segment reviews, summaries and readback records. A readback_complete checkpoint is written only after all source fragments were sent and acknowledged; raw provider requests/responses stay private in maintenance_calls. Snapshot directory_metrics and previous_maintenance are decision inputs; prior model conclusions are never fresh independent evidence. Model input uses an explicit byte-based conservative text-token budget (60% input), with separate image reservation; oversized indivisible values fail instead of being truncated. A configured vision provider must report a successful image read before it counts as evidence; default vision is disabled.

Evidence references may use kind=interface to cite the original interface in the fixed snapshot. Directory changes and inferred descriptions can use this evidence; parameter relations and enum values still require captured field/fact support. Summary/annotation/index references are navigation and never independent evidence. Index reads return lossless original index data directly to the planner; they do not add field-review coverage. Invalid plan actions receive bounded validation feedback and remain unpublishable unless repaired. replace_catalog requires strategy=full; insert uses set_directory and assign_interface. Missing recent samples alone cannot remove already observed enum values.

Review dispositions and reference kinds are explicitly enumerated in the shared Schema. Provider prompts use the corresponding branch and reachable definitions from this Schema, not handwritten shape examples. Runtime semantic validation remains authoritative for allowed evidence roles and publication.


There is one production generation path: explicit POST maintenance-runs -> MaintenanceEngine. Legacy catalog-create/catalog-run/catalog-preview CLI generation and its generator/store execution ports are retired. Historical candidate and catalog version readers and activation endpoints remain for existing data; they cannot generate candidates.

Strategies constrain directory changes, not how much evidence is reviewed. keep preserves catalog and display groups while allowing semantic maintenance. insert preserves existing directory nodes, already-classified memberships and existing groups; it may add nodes, classify unclassified interfaces and add groups. partial edits the existing catalog by explicit actions and cannot replace_catalog. full may replace_catalog or combine explicit actions. All modes still use complete project snapshot review and the same publication checks.

Small original read requests are included in the next planning call and marked read only after its successful valid response. Oversized sources and images retain dedicated bounded reading. Stored source requests remain exact and summaries are not original evidence. A new run always begins from an immutable snapshot; incoming data is not silently spliced in.


## Frozen input contract (2.0)

New snapshots contain `inputs`: processed structural observation materials, selected frozen source descriptors and explicit `gaps` counters. A single PostgreSQL read statement fixes interface definitions, stored assessments/materials, facts, selected source membership and work counts. Existing evidence/retention and catalog locks protect the surrounding assembly. Actual final snapshot size is checked before persistence. Source selection is the union of fact samples, original records of included structural observations, and pending/failed capture events; it does not promise to include every historical repeat. Every available selected original is pinned atomically with the snapshot.

Observation materials retain the stored `ObservationAssessment` unchanged. Where a needed observation field cannot be described by the historical extractor, a separate `reconstructed_definition` is derived from retained raw data using the existing extractor/path rules. Its identity must match the admitted identity. This is read-only snapshot material, not a recalculated historical assessment, schema adoption or new revision. Missing raw/definitions remain explicit gaps. A field whose definition is unavailable keeps its observation reference and an unknown schema entry rather than disappearing from review.

The same field builder, parser and review path serve adopted and observation fields. Adopted field IDs stay stable. Observation IDs include the original project/interface/environment/ingestion/location/path. Review coverage includes every declared field/unit of both kinds; it is not a claim that incomplete capture became complete or that pending observations have been processed. Semantic write targets remain adopted FieldRefs; no revision ID is invented for observation fields.

Navigation retains evidence rule, reassessment, transform, scope and search-completeness flags. Long summary values are explicitly listed in `omitted_fields`, with the fact reference available for exact reads. Legacy/needs_reassessment facts are visible but cannot be used as independently validated evidence in a new candidate. Their original sources and current interface data remain available under the same scoped read rules.

Frozen source descriptors include project/environment, actor/producer/record, captured_at, context, raw content hash and extraction coverage. The engine resolves source IDs only inside its snapshot; reads use the frozen hash/metadata and validate the bytes, not a later live context lookup. Source or observation reads do not add field-review coverage. No model is called by creating or reading a snapshot; existing explicit-task execution remains the sole model entry.

For compatibility, missing/null `inputs` identifies an old snapshot and remains readable. It cannot be resumed or newly published as a complete 2.0 maintenance result: `SNAPSHOT_INPUTS_UNAVAILABLE_RECREATE` requires a fresh explicit run. Existing published versions and catalog-only compatibility operations are retained. Consumers validating snapshot field references must sync the 2.0 contract before using new snapshots. Upload contracts, login, directory list and observed-document APIs do not change.
